What Is a Linked List?

The structure, the JS implementation, and why linked lists exist despite arrays being more common.

A linked list is a sequence of nodes where each node contains a value and a pointer to the next node. Unlike arrays, nodes don't occupy contiguous memory — they're scattered in memory and linked by pointers. This gives O(1) insert/delete at a known position but O(n) access by index.

class ListNode {
    constructor(val = 0, next = null) {
        this.val = val;
        this.next = next;

// Build a linked list from array — useful for testing
function buildList(arr) {
    const dummy = new ListNode(0);
    let curr = dummy;
    for (const val of arr) {
        curr.next = new ListNode(val);
        curr = curr.next;
    }
    return dummy.next;
}

// Traverse — always check for null BEFORE accessing .next or .val
function traverse(head) {
    let curr = head;
    while (curr !== null) {   // ALWAYS check !== null, not just truthiness
        console.log(curr.val);
        curr = curr.next;
    }
}

// Length of list
function length(head) {
    let count = 0, curr = head;
    while (curr) { count++; curr = curr.next; }
    return count;
}

Section 02

5 Core Patterns

Every linked list problem uses one of these patterns. Identify the pattern → apply the template.
Pattern 01
Fast / Slow Pointers
Two pointers at different speeds. Slow moves 1 step, fast moves 2. When fast reaches end, slow is at the middle. If fast meets slow, there's a cycle. Floyd's Cycle Detection algorithm.
Middle of list · Detect cycle · Find cycle start · Kth from end
Pattern 02
In-Place Reversal
Reverse a list or portion of it using prev, curr, next pointers. Save next before overwriting. Move prev and curr forward. Classic O(1) space reversal.
Reverse Linked List · Reverse Sublist · Palindrome Check · Reorder List
Pattern 03
Dummy Head (Sentinel)
Create a dummy node before head. Attach new list to dummy.next. Eliminates special cases for empty list or modifying head. Return dummy.next as the answer.
Merge Two Lists · Remove Nth from End · Remove Duplicates · Partition List
Pattern 04
Two Pointers (Different Start)
Start two pointers at different positions. Classic: advance one pointer k steps, then move both until far one hits end — near one is at Nth from end. Also used for intersection detection.
Remove Nth From End · Intersection of Two Lists · Skip ahead k nodes
Pattern 05
Merge / Split
Divide list into parts, process, recombine. Used in merge sort on lists, zip two lists, reorder by alternating nodes, interleave multiple lists.
Merge K Sorted Lists · Sort List · Reorder List · Odd Even Linked List

Section 03

Interview Framework

What to say, draw, and think about before writing any linked list code.
1
Draw the list — always
Before writing a single line: draw boxes for nodes with arrows. This is non-negotiable for linked list problems. Interviewers expect you to draw. It clarifies your thinking and prevents null pointer errors. Draw the before and after state for pointer changes.
"Let me draw this out. [Boxes: 1→2→3→4→5→null]. For reversing, I need prev, curr, and next. Let me trace through one step: prev=null, curr=1. Save next=2. Set curr.next=prev (null). Move prev to 1, curr to 2. Continue."
2
Ask: singly or doubly linked? Circular?
Singly linked (just .next) is most common in interviews. Doubly linked has .prev too — used in LRU cache. Circular has the tail's .next pointing back to head — changes the null check logic. Always clarify.
"Is this a singly linked list, or does it have a previous pointer? And can it be circular, or does it always terminate at null?"
3
Identify the pattern — say it aloud
Name the pattern before coding. "This is a fast/slow pointer problem." "This is an in-place reversal." "I'll use a dummy head." Naming the pattern shows the interviewer you have a structured approach, not just intuition.
"I'll use the fast/slow pointer pattern — slow moves 1 step, fast moves 2. When fast reaches the end, slow will be at the middle. Then I can split the list there."
4
Save next pointer BEFORE reassigning
The cardinal rule of linked list manipulation. When you do curr.next = prev, you lose the reference to the next node. Always: const next = curr.next; THEN reassign curr.next. This is the most common bug beginners make in linked list problems — forgetting to save next before overwriting.
"Before I change curr.next, I always save the next node: const next = curr.next. Then I can safely overwrite curr.next = prev without losing the rest of the list."
5
Handle edge cases: empty, single node, two nodes
The most common edge cases: empty list (head = null), single node, and lists with exactly two nodes (many reversal/partition bugs appear here). Mention them before coding. Test your solution mentally with a 1-node and 2-node list.
"Edge cases: if head is null or head.next is null, return head immediately — nothing to do. Let me also trace through a 2-node list to make sure my reversal handles that correctly."
The most common linked list bugs — memorize these:

✗ Forgetting to save next before reassigning curr.next → lose rest of list
✗ Not checking curr !== null before accessing curr.val or curr.next → NullPointerException
✗ Off-by-one in fast/slow: fast starts at head vs head.next affects middle position
✗ Not returning dummy.next — returning dummy instead (the sentinel itself)
✗ Infinite loops in cycle detection — forgetting to check fast !== null && fast.next !== null
✗ Losing the new head after reversal — save it before starting the reversal loop
Section 04

The 5 Templates

Memorize these skeletons. They apply to 90% of linked list problems.
JavaScriptTemplate 1 — In-Place Reversal
function reverseList(head) {
    let prev = null;
    let curr = head;

    while (curr !== null) {
        const next = curr.next;  // STEP 1: save next BEFORE overwriting
        curr.next = prev;        // STEP 2: reverse the pointer
        prev = curr;             // STEP 3: advance prev
        curr = next;             // STEP 4: advance curr (using saved next)
    }

    return prev;  // prev is now the new head
}
// Trace: 1→2→3→null
// Step 1: next=2, 1.next=null, prev=1, curr=2
// Step 2: next=3, 2.next=1,    prev=2, curr=3
// Step 3: next=null, 3.next=2, prev=3, curr=null → exit
// Return prev=3 (new head). Result: 3→2→1→null ✓
JavaScriptTemplate 2 — Fast/Slow Pointers
// Find middle of list
function findMiddle(head) {
    let slow = head, fast = head;

    while (fast !== null && fast.next !== null) {
        slow = slow.next;        // slow: 1 step
        fast = fast.next.next;   // fast: 2 steps
    }

    return slow; // slow is at the middle
}
// For [1,2,3,4,5]: returns node 3 (exact middle)
// For [1,2,3,4]:   returns node 3 (second of two middles)

// Detect cycle
function hasCycle(head) {
    let slow = head, fast = head;

    while (fast !== null && fast.next !== null) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow === fast) return true; // they met → cycle!
    }

    return false; // fast hit null → no cycle
}
JavaScriptTemplate 3 — Dummy Head
function processWithDummy(head) {
    const dummy = new ListNode(0); // sentinel: simplifies edge cases
    let curr = dummy;

    // Build new list attached to dummy
    let node = head;
    while (node !== null) {
        if (/* condition to keep node */) {
            curr.next = node;
            curr = curr.next;
        }
        node = node.next;
    }
    curr.next = null; // IMPORTANT: terminate the new list

    return dummy.next; // NOT dummy — return the actual head
}
// Why dummy: without it, you'd need special case for empty result
// and for "head changes" (e.g. removing the first node)
// With dummy: always return dummy.next — works for all cases
JavaScriptTemplate 4 — Two Pointer (k apart) — Nth from end
function removeNthFromEnd(head, n) {
    const dummy = new ListNode(0);
    dummy.next = head;
    let fast = dummy, slow = dummy;

    // Advance fast n+1 steps ahead of slow
    for (let i = 0; i <= n; i++) fast = fast.next;

    // Move both until fast hits null
    while (fast !== null) {
        slow = slow.next;
        fast = fast.next;
    }

    // slow is now at the node BEFORE the one to delete
    slow.next = slow.next.next;

    return dummy.next;
}
// Why n+1 not n: we want slow to stop BEFORE the target node
// so we can do slow.next = slow.next.next (skip the target)
JavaScriptTemplate 5 — Merge Two Sorted Lists
function mergeTwoLists(l1, l2) {
    const dummy = new ListNode(0);
    let curr = dummy;

    while (l1 !== null && l2 !== null) {
        if (l1.val <= l2.val) {
            curr.next = l1;
            l1 = l1.next;
        } else {
            curr.next = l2;
            l2 = l2.next;
        }
        curr = curr.next;
    }

    // Attach remaining nodes (whichever list is non-null)
    curr.next = l1 !== null ? l1 : l2;

    return dummy.next;
}
// Time: O(n + m). Space: O(1) — no new nodes, just pointer rewiring

Problem 01 of 05Easy
Reverse Linked List
LeetCode #206 · leetcode.com/problems/reverse-linked-list
1
Problem: Reverse a singly linked list. Return the new head. Must be done in-place (O(1) space).
2
Pattern: In-place reversal (Template 1). Three pointers: prev (starts null), curr (starts at head), next (temp storage).
3
The 4-step body: (1) Save next = curr.next. (2) Reverse: curr.next = prev. (3) Advance: prev = curr. (4) Advance: curr = next. Repeat until curr is null. Return prev (new head).
4
Recursive version: Reverse the rest of the list, then make the last node point back to the current node. Elegant but O(n) stack space — iterative is preferred for interviews.
Interviewer
Reverse a linked list in-place.
You
Let me draw it. [Draws 1→2→3→null]. I need to turn this into 3→2→1→null. I'll use three pointers: prev (initially null), curr (starts at head), and a temp for the next node.
You
At each step: save curr.next, then point curr.next backward to prev, advance both prev and curr. The key is saving next BEFORE overwriting curr.next — otherwise I'd lose the rest of the list.
Interviewer
Can you do it recursively?
You
Yes. Recursively reverse the rest of the list, then make head.next.next point back to head, and set head.next to null. Elegant but O(n) stack space for the recursion. The iterative version is O(1) space — preferred for large lists. Which would you like me to code?
Interviewer
Code the iterative version.
You
[codes while narrating] prev=null, curr=head. While curr is not null: save next=curr.next, set curr.next=prev, advance prev=curr, advance curr=next. Return prev — that's the new head after the loop.
JavaScriptReverse Linked List — iterative O(n) time, O(1) space
function reverseList(head) {
    let prev = null;
    let curr = head;

    while (curr !== null) {
        const next = curr.next; // save before overwriting
        curr.next = prev;       // reverse pointer
        prev = curr;            // advance prev
        curr = next;            // advance curr
    }

    return prev; // new head
}

// Recursive version (O(n) stack space)
function reverseListRecursive(head) {
    if (!head || !head.next) return head; // base: 0 or 1 node
    const newHead = reverseListRecursive(head.next);
    head.next.next = head; // make next node point back to current
    head.next = null;      // current becomes the tail
    return newHead;
}
Time: O(n) — visit each node once Space: O(1) iterative / O(n) recursive (call stack)
  • Empty list (head=null): curr=null, while loop doesn't execute. Return prev=null. Correct.
  • Single node [1]: Save next=null. curr.next=prev=null (no change). prev=1, curr=null. Return prev=node1. Correct.
  • Two nodes [1→2]: Step 1: next=2, 1.next=null, prev=1, curr=2. Step 2: next=null, 2.next=1, prev=2, curr=null. Return 2. Result: 2→1→null. Correct.
  • Why prev starts at null: The tail of the reversed list should point to null. prev=null ensures the original head (which becomes the tail) correctly points to null after reversal.
Problem 02 of 05Easy
Linked List Cycle + Cycle Start
LeetCode #141 + #142 · #141 · #142
1
Problem #141: Does the linked list have a cycle? Return true/false. A cycle means a node's next pointer points back to a previous node.
2
Floyd's Algorithm: Slow moves 1 step, fast moves 2. If there's a cycle, fast will "lap" slow and they'll meet inside the cycle. If no cycle, fast reaches null. O(1) space — no Set needed.
3
Problem #142 — find where cycle starts: After slow and fast meet (inside cycle), reset slow to head. Move both one step at a time. Where they meet again = cycle start node. This is a mathematical property of Floyd's algorithm.
4
Why the math works for #142: Let F = distance from head to cycle start. C = cycle length. When they first meet, slow has traveled F+a steps, fast has traveled F+a+nC steps (for some integer n). Since fast = 2×slow: 2(F+a) = F+a+nC → F = nC-a. So from the meeting point, a is the distance already covered inside the cycle. Resetting slow to head and advancing both by 1 means they meet exactly at the cycle start after F steps.
Interviewer
Detect if a linked list has a cycle.
You
I'll use Floyd's cycle detection — fast/slow pointers. Slow moves one step, fast moves two. If they ever point to the same node, there's a cycle. If fast reaches null, there's no cycle. O(n) time, O(1) space — no HashSet needed.
Interviewer
Why does this work? Why do they always meet if there's a cycle?
You
Once both pointers are inside the cycle, fast gains one node on slow each iteration — it's like fast is chasing slow around a circular track. The gap between them decreases by 1 each step. Eventually the gap reaches 0 and they're at the same node. The cycle ensures they can't "pass" each other without meeting.
Interviewer
Can you also find where the cycle starts?
You
Yes — LeetCode #142. After slow and fast meet inside the cycle, reset slow to head. Now move both pointers one step at a time. Where they meet again is the cycle start. It's a mathematical property: the distance from head to cycle start equals the distance from the meeting point to cycle start (going forward). So both pointers arrive at the start at the same time.
JavaScriptCycle Detection + Cycle Start (Floyd's Algorithm)
// #141: Has cycle?
function hasCycle(head) {
    let slow = head, fast = head;

    while (fast !== null && fast.next !== null) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow === fast) return true;
    }

    return false;
}

// #142: Find cycle start node
function detectCycle(head) {
    let slow = head, fast = head;

    // Phase 1: detect cycle
    while (fast !== null && fast.next !== null) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow === fast) break; // they met inside cycle
    }

    // No cycle: fast hit null
    if (fast === null || fast.next === null) return null;

    // Phase 2: find cycle start
    slow = head; // reset slow to head
    while (slow !== fast) {
        slow = slow.next; // both move 1 step
        fast = fast.next;
    }

    return slow; // meeting point = cycle start
}
Time: O(n) — both phases linear Space: O(1) — no extra data structures
  • Empty list: fast=null immediately. Return false. Correct.
  • Single node, no cycle: fast.next=null. Loop exits. Return false.
  • Single node with cycle to itself: fast.next.next goes back to head=slow. They meet on next iteration. Return true.
  • Why check fast !== null AND fast.next !== null: fast.next.next can throw NullPointerException if fast.next is null. Both checks are needed. If either is null, no cycle → return false.
  • HashSet alternative: Add each node to a Set. If seen again, cycle found. O(n) time and space. Less elegant but easier to remember. Floyd's is O(1) space.
Problem 03 of 05Easy
Merge Two Sorted Lists
LeetCode #21 · leetcode.com/problems/merge-two-sorted-lists
1
Problem: Merge two sorted linked lists into one sorted list. Return the head of the merged list. Do it in-place (no new nodes, just rewire pointers).
2
Dummy head pattern: Create a dummy node. Use a curr pointer to build the merged list. At each step, compare l1.val and l2.val, attach the smaller node, advance that pointer.
3
After the loop: One list is exhausted. Attach the remaining non-null list directly — no need to iterate further. curr.next = l1 !== null ? l1 : l2.
4
Return dummy.next — the actual head of the merged list. The dummy itself is discarded.
Interviewer
Merge two sorted linked lists in-place.
You
I'll use a dummy head to avoid special-casing the head of the merged list. I compare the current nodes of both lists, attach the smaller one to curr.next, and advance that list's pointer. When one list runs out, I attach the remaining nodes directly — they're already sorted.
Interviewer
Why use a dummy head?
You
Without a dummy, I'd need to separately handle which list's first node becomes the merged head, and then special-case when the result list is empty. With dummy, I always have a node to attach to — curr.next — regardless of which case I'm in. At the end, dummy.next is the actual head. The dummy itself is just discarded. It eliminates all special cases at the cost of one extra node allocation.
Interviewer
What if one list is empty?
You
If l1 is null: the while loop never runs. curr.next = l2. Return dummy.next = l2. Correct. Same for l2 being null. Both empty: return dummy.next = null. Correct — empty merged list.
JavaScriptMerge Two Sorted Lists — O(n+m)
function mergeTwoLists(l1, l2) {
    const dummy = new ListNode(0); // sentinel node
    let curr = dummy;

    while (l1 !== null && l2 !== null) {
        if (l1.val <= l2.val) {
            curr.next = l1;
            l1 = l1.next;
        } else {
            curr.next = l2;
            l2 = l2.next;
        }
        curr = curr.next; // advance the merged list pointer
    }

    // Attach remaining nodes (one of l1, l2 is null — the other may not be)
    curr.next = l1 !== null ? l1 : l2;

    return dummy.next; // dummy.next is the true head of merged list
}
Time: O(n + m) — n and m are lengths of the two lists Space: O(1) — in-place pointer rewiring, no new nodes
  • Both empty: While loop doesn't run. curr.next = null. Return dummy.next = null.
  • One empty: While loop doesn't run. curr.next = the non-null list. Return it.
  • All values equal: l1.val <= l2.val always true — takes all from l1 first, then l2. Result still sorted (stable).
  • After the while loop: Exactly one of l1 or l2 is non-null. The remaining nodes are already in sorted order — no need to traverse, just attach directly with curr.next = remaining.
  • Recursive version: if (!l1) return l2; if (!l2) return l1; if l1.val <= l2.val: l1.next = mergeTwoLists(l1.next, l2); return l1; else l2.next = mergeTwoLists(l1, l2.next); return l2. Elegant but O(n+m) stack space.
Problem 04 of 05Medium
Remove Nth Node From End of List
LeetCode #19 · leetcode.com/problems/remove-nth-node-from-end-of-list
1
Problem: Remove the Nth node from the end of the list in one pass. N is guaranteed valid.
2
Two pointer approach: Advance fast pointer n+1 steps ahead of slow (using dummy as starting point for both). Then move both one step at a time until fast is null. Slow is now at the node BEFORE the one to delete.
3
Why n+1 not n: We want to delete slow.next (not slow itself). So slow must stop one node BEFORE the target. n+1 gap gives us this — when fast is null, slow is exactly at the predecessor of the Nth-from-end node.
4
Why dummy head: If n equals the length of the list, we need to delete the head node. Without dummy, there's no "node before head" to update. With dummy, slow can stop at dummy and do dummy.next = dummy.next.next to delete the original head.
Interviewer
Remove the Nth node from the end in one pass.
You
Two-pass solution: first count the length, then remove the (len-n+1)th node. But you said one pass. So: two pointers starting at a dummy node. I advance fast n+1 steps ahead, then move both until fast is null. Slow ends up at the node before the one to delete.
Interviewer
Why n+1 steps ahead and not n?
You
I want slow to stop at the predecessor of the target node, not the target itself. To delete slow.next, I need slow to be one before the target. If I advance fast n steps (not n+1), slow stops AT the target — I can't easily delete it without a previous pointer. The n+1 gap puts slow one earlier, giving me the previous node.
Interviewer
What if n equals the length — removing the head?
You
That's why I use a dummy head. Both fast and slow start at dummy. Fast advances n+1 steps. If n equals the length, fast ends up at null (off the end). Slow stays at dummy. slow.next = slow.next.next removes the original head. Return dummy.next as the new head.
JavaScriptRemove Nth From End — one pass, O(n)
function removeNthFromEnd(head, n) {
    const dummy = new ListNode(0);
    dummy.next = head;
    let fast = dummy, slow = dummy;

    // Advance fast n+1 steps ahead
    for (let i = 0; i <= n; i++) {
        fast = fast.next;
    }

    // Move both until fast is null
    while (fast !== null) {
        slow = slow.next;
        fast = fast.next;
    }

    // slow is now at the node BEFORE the one to delete
    slow.next = slow.next.next;

    return dummy.next;
}
Time: O(n) — single pass (fast traverses the full list) Space: O(1) — two pointers only
  • n = length (remove head): Fast advances n+1 steps from dummy → off end (null). Slow stays at dummy. slow.next = slow.next.next → removes original head. Return dummy.next.
  • n = 1 (remove tail): Fast advances 2 steps. Both move until fast is null. Slow at second-to-last node. slow.next = null. Tail removed.
  • List of 1 node, n=1: Dummy→node1→null. Fast advances 2 steps: dummy.next=node1, node1.next=null. Fast is null. Slow stays at dummy. slow.next = slow.next.next = null. Return dummy.next = null. Correct.
  • The loop bound is i <= n (n+1 iterations): We advance n+1 times from dummy. If list has length L, fast starts at dummy (position -1) and after n+1 steps is at position n. When both advance, slow will be at position L-n-1, which is the predecessor of the Nth-from-end node.
Problem 05 of 05Medium
Reorder List
LeetCode #143 · leetcode.com/problems/reorder-list
1
Problem: Reorder list: L0→L1→L2→...→Ln becomes L0→Ln→L1→Ln-1→L2→Ln-2→... In-place, no extra space.
2
Three-step approach: (1) Find the middle using fast/slow pointers. (2) Reverse the second half. (3) Merge the two halves by alternating nodes. This combines all three major patterns.
3
Step 1 — Find middle: Slow at middle when fast reaches end. Split: slow.next = null to separate the two halves.
4
Step 2 — Reverse second half: Reverse the second half using Template 1. Now second half points in reverse order (from Ln back to the middle).
5
Step 3 — Interleave: Two pointers, one in each half. Alternately take from first half, then second half. Wire them together.
Interviewer
Reorder list: L0→Ln→L1→Ln-1→... In-place.
You
This combines three patterns. Step 1: find the middle with fast/slow pointers, split into two halves. Step 2: reverse the second half in-place. Step 3: interleave the two halves by alternating nodes.
You
For [1,2,3,4,5]: middle is 3. First half: 1→2→3. Second half reversed: 5→4. Interleave: take 1 from first, 5 from second, 2 from first, 4 from second, 3 from first. Result: 1→5→2→4→3.
Interviewer
Why not just use a stack or array?
You
Using an array of nodes: O(n) space. Or using a stack to get the second half in reverse: O(n) space. The three-step in-place approach uses O(1) space — no extra storage. In an interview where they say "in-place", the O(1) space solution is expected. The array approach is simpler and totally fine if O(n) space is acceptable.
JavaScriptReorder List — 3-step in-place O(n), O(1) space
function reorderList(head) {
    if (!head || !head.next) return;

    // Step 1: Find middle (slow will be at middle)
    let slow = head, fast = head;
    while (fast.next && fast.next.next) {
        slow = slow.next;
        fast = fast.next.next;
    }

    // Split: disconnect first and second halves
    let secondHalf = slow.next;
    slow.next = null; // terminate first half

    // Step 2: Reverse second half
    let prev = null, curr = secondHalf;
    while (curr) {
        const next = curr.next;
        curr.next = prev;
        prev = curr;
        curr = next;
    }
    secondHalf = prev; // new head of reversed second half

    // Step 3: Interleave first and (reversed) second halves
    let first = head, second = secondHalf;
    while (second !== null) {
        const firstNext  = first.next;
        const secondNext = second.next;
        first.next  = second;  // wire: first → second
        second.next = firstNext; // wire: second → first's old next
        first  = firstNext;  // advance both pointers
        second = secondNext;
    }
}
// [1,2,3,4,5] → split: [1,2,3] [4,5] → reverse second: [5,4]
// interleave: 1→5→2→4→3 ✓
Time: O(n) — three linear passes Space: O(1) — in-place pointer manipulation
  • Even length [1,2,3,4]: Middle is 2 (slow stops at 2). First: 1→2. Second reversed: 4→3. Interleave: 1→4→2→3.
  • Length 1 or 2: Guard at top returns early. No reordering needed.
  • Why fast.next && fast.next.next (not fast && fast.next): This ensures slow stops at the LEFT middle for even lists. [1,2,3,4] → slow stops at 2, not 3. This gives first half length ≥ second half length, which matters for the interleaving step.
  • The simpler O(n) space version: Collect all nodes into an array, use two-pointer (L and R) to rewire. Easier to code correctly in an interview. Know both and offer the O(1) version as the optimal.

15 Interview Questions

Answer out loud first. These are real linked list questions from product company interviews in Bangalore.
CoreWhy must you save `next` before reassigning `curr.next`?▼
Because reassigning curr.next destroys the reference to the rest of the list. In a singly linked list, the only way to reach node 3 from node 2 is through 2.next. If you do curr.next = prev (to reverse), the reference to node 3 is gone forever — you can't advance curr anymore. Solution: always save const next = curr.next BEFORE any pointer reassignment. Then you can do curr.next = prev, curr = next safely. This is THE cardinal rule of linked list manipulation. Mention it proactively in interviews: "Before I overwrite curr.next, I'll save the next pointer." It signals experience.
PatternExplain Floyd's cycle detection. Why does fast lapping slow prove a cycle?▼
Floyd's: slow moves 1 step, fast moves 2. If there's no cycle, fast reaches null first — no meeting. If there's a cycle: once both pointers enter the cycle, fast gains 1 node on slow per iteration (because fast moves 2, slow moves 1 — net gain of 1). The gap between fast and slow decreases by 1 each step (in the cycle's direction). Eventually the gap becomes 0 — they're at the same node. This is inevitable: starting from any gap G, after G steps, gap = 0. They can't "pass" each other because they're moving in the same direction in a cycle — if fast is G steps ahead and gains 1 per step, after G-1 steps fast is 1 step ahead, then after one more step they're at the same node. O(n) time, O(1) space — no HashSet needed.
CoreWhy use a dummy head? When is it necessary?▼
A dummy (sentinel) node is a fake node placed before the actual head. It gives you a "node before the head" — useful when the operation might change the head itself. Necessary when: (1) Building a new list — always have something to attach to, even if the result is empty. Return dummy.next. (2) Deleting the head node — without dummy, there's no previous node to update. With dummy, treat it like any other deletion: dummy.next = dummy.next.next. (3) Merging lists — both lists might start their merge from the very first node; dummy avoids the special case of "which list's head becomes the merged head." Pattern: create dummy, return dummy.next. The dummy is discarded. Cost: one extra node allocation — always worth it for simpler code.
InterviewHow do you find the middle of a linked list? What's the off-by-one choice?▼
Use fast/slow pointers. Both start at head. Slow moves 1, fast moves 2. When fast reaches the end, slow is at the middle. The off-by-one choice: for an even-length list [1,2,3,4], there are two middle nodes (2 and 3). The choice of starting position determines which: (1) fast starts at head: when fast reaches the last node, slow is at position n/2 (left middle — 2 for [1,2,3,4]). (2) fast starts at head.next: when fast reaches null, slow is at the right middle (3 for [1,2,3,4]). For splitting a list (like in merge sort or Reorder List): use the "left middle" variant — while(fast.next && fast.next.next). This ensures first half has length ≥ second half. For finding the second half start (like palindrome check): use "right middle" variant — while(fast && fast.next).
PatternHow do you reverse a linked list iteratively? Trace through an example.▼
Three pointers: prev=null, curr=head, next (temp). Loop while curr !== null: (1) save next=curr.next. (2) curr.next=prev (reverse pointer). (3) prev=curr. (4) curr=next. Return prev. Trace for 1→2→3→null: Initial: prev=null, curr=1. Step 1: next=2, 1.next=null, prev=1, curr=2. Step 2: next=3, 2.next=1, prev=2, curr=3. Step 3: next=null, 3.next=2, prev=3, curr=null. Loop exits. Return prev=3. Result: 3→2→1→null. Why prev starts null: the original head (1) becomes the tail and should point to null. Starting prev=null ensures this automatically. Memorize the 4-step body and you can code this without thinking.
InterviewHow do you detect the intersection of two linked lists?▼
LeetCode #160. Two approaches: (1) HashSet: traverse list A, add all nodes to a Set. Traverse list B — if a node is in the Set, that's the intersection. O(n+m) time, O(n) space. (2) Two pointers (O(1) space): traverse both lists simultaneously. When pointer A reaches the end of A, redirect it to head of B. When pointer B reaches end of B, redirect to head of A. They will meet at the intersection node (or both reach null at the same time if no intersection). Why: both pointers travel the same total distance: len(A) + len(B). When they reach the end of their respective lists and switch, they're equidistant from the intersection. After switching, they converge. If no intersection: both reach null simultaneously after len(A)+len(B) steps.
TrapWhat are the edge cases to check before submitting any linked list solution?▼
Always mentally trace these before submission: (1) Empty list (head=null) — does your code return null/0/false correctly? (2) Single node — no next pointer to follow, reversal returns the node itself. (3) Two nodes — the minimal non-trivial case. Many reversal/cycle/merge bugs appear here. (4) Deleting the head — dummy head pattern handles this. (5) Cycle edge case: single node cycling to itself (node.next = node). Fast/slow: fast.next.next = node = slow, meets on first iteration. (6) n = length (Remove Nth): deletes the head. (7) All same values. (8) Already sorted / already reversed. For fast/slow: always check fast !== null AND fast.next !== null before accessing fast.next.next.
InterviewHow would you check if a linked list is a palindrome in O(n) time, O(1) space?▼
Three steps: (1) Find the middle using fast/slow pointers. (2) Reverse the second half in-place. (3) Compare first half with reversed second half node by node. If all values match, it's a palindrome. Reset the list to its original state if required (reverse the second half back). O(n) time, O(1) extra space. Walk-through: [1,2,2,1] → middle is second 2. Reverse second half: [1] reversed = [1]. Compare: first=1,2 and second=1,2 (reversed). Match — palindrome. Edge cases: odd length [1,2,1] — middle is 2. Don't include middle in either comparison half. The fast.next && fast.next.next condition for finding middle gives the "left middle," which splits the odd list as [1,2] and [1], reversed [1]. Compare 1=1, done. Common interview follow-up: "Now do it without modifying the list" → either O(n) space with a Stack, or the O(n) time O(1) space with reversal + restoration.
PatternExplain the Merge K Sorted Lists approaches and their complexities.▼
Two efficient approaches: (1) Min-Heap (Priority Queue): Insert the head of all k lists into a min-heap. Extract the minimum, add to result. Insert that node's next into the heap. Repeat. Total nodes = N, each node inserted/extracted from heap once. O(N log k) time — log k for heap operations. O(k) space for the heap. (2) Divide and Conquer: Merge lists pairwise in rounds. Round 1: merge pairs → k/2 lists. Round 2: merge those → k/4 lists. Continue until 1 list. Each round touches all N nodes — O(N) per round. log k rounds → O(N log k). O(log k) space for recursion. Both are O(N log k). Naive brute force: merge one by one → O(Nk). Min-heap is preferred for interviews — it's cleaner and the complexity is explicit. Know the heap approach cold.
InterviewHow would you implement an LRU Cache? What data structures?▼
LRU Cache requires O(1) get and O(1) put. Data structures: HashMap + Doubly Linked List. HashMap: key → node. O(1) lookup. Doubly Linked List: nodes in LRU order. Most recently used at head, least recently used at tail. Why doubly linked: O(1) deletion anywhere (need prev pointer). Operations: get(key): if in map, move node to head. Return value. put(key, value): if exists, update + move to head. If not: create node, add to head, add to map. If over capacity, remove tail node + remove from map. Two dummy sentinels (dummyHead and dummyTail) eliminate edge cases for empty list. The HashMap gives O(1) access, the DLL gives O(1) reordering and eviction. This is a very common system design + DSA hybrid question — know it as a standalone concept.
TrapWhat's the difference between deleting a node with access to its predecessor vs without?▼
Normal deletion: you have a pointer to the predecessor. Set prev.next = curr.next. O(1) — standard linked list deletion. Deletion without predecessor (LeetCode #237): the problem gives you only the node to delete, not the previous node. Trick: copy the NEXT node's value into the current node, then delete the next node. curr.val = curr.next.val; curr.next = curr.next.next. This works because the node's identity is its memory address — by overwriting its value with the next node's value and removing the next node, we effectively "deleted" the target node without needing its predecessor. Important caveat: this only works if the node is NOT the tail (the tail has no next to copy from). LeetCode guarantees it's not the tail in #237. In a real interview, mention this caveat.
CoreWhat is the time complexity of common linked list operations vs arrays?▼
Arrays: O(1) access by index, O(n) insert/delete in middle (shifting), O(1) amortized push/pop at end. Linked Lists: O(n) access by index (must traverse), O(1) insert/delete at KNOWN position (need the predecessor node), O(n) to FIND a position. So: LL isn't faster at deletion — you still need O(n) to find the node. The O(1) delete advantage only applies when you already have a pointer to the predecessor. In practice: arrays win for cache performance (contiguous memory). LLs win for: implementing queues/deques with O(1) front operations, LRU cache (O(1) reorder with doubly LL + map), adjacency lists in graphs, when you have many mid-list insertions/deletions with direct node references. For most competitive programming problems, arrays are preferred over linked lists — LLs appear in problems specifically designed to test pointer manipulation.
InterviewHow do you add two numbers represented as linked lists? (#2)▼
Each list represents a number in reverse order (ones digit first). Traverse both lists simultaneously, digit by digit, adding values plus carry. Create a new result node for each sum. Code: dummy head, l1 and l2 pointers, carry=0. While l1, l2, or carry is non-null/non-zero: sum = (l1?.val || 0) + (l2?.val || 0) + carry. carry = Math.floor(sum / 10). digit = sum % 10. Append digit node. Advance l1 and l2. Key points: carry can create an extra digit after both lists are exhausted (e.g., 999 + 1 = 1000 needs a new node for the leading 1). Use optional chaining or null checks when one list is shorter. Return dummy.next. O(max(n, m)) time, O(max(n, m)) space for the result list.
InterviewHow do you sort a linked list? What's the optimal approach?▼
Optimal: Merge Sort on linked list. O(n log n) time, O(log n) space (recursion stack), or O(1) extra space with bottom-up merge sort. Why merge sort and not quicksort: quicksort needs random access for pivot selection — O(n) to reach a random element. Merge sort only needs sequential access — perfect for linked lists. Also merge sort is stable for linked lists. Algorithm: (1) Find middle with fast/slow. (2) Split into two halves (set slow.next = null). (3) Recursively sort each half. (4) Merge the two sorted halves. Base case: list of 0 or 1 nodes is already sorted. This is also how merge sort is typically taught using linked lists — interviewers often ask it to test if you can apply divide-and-conquer to a non-array structure.
CoreWhat is the fast/slow pointer used for, beyond cycle detection?▼
Fast/slow (Floyd's) is a general technique that solves several linked list problems: (1) Find middle: when fast reaches end, slow is at middle. (2) Detect cycle: if they meet, cycle exists. (3) Find cycle start: after meeting, reset slow to head, advance both 1 step — they meet at cycle start. (4) Kth from end: advance fast k steps, then advance both — when fast reaches null, slow is at kth from end (similar to the "gap" two-pointer). (5) Palindrome check: find middle, reverse second half, compare. (6) Happy number (#202): detect cycle in the "sum of squares of digits" sequence — uses Floyd's on a numerical sequence, not a literal linked list. The fast/slow pattern generalizes to any sequence where you might have a cycle — graph problems, math sequences, not just linked lists.
