Section 01

The Core Idea

What the pattern is, why it exists, and exactly when to recognize it during an interview.

Almost every array problem starts with nested loops. For each element, check all other elements — that's O(n²). The question is: can you trade space for time? A HashMap (or JavaScript's Map/Object) gives you O(1) lookup, making the nested loop unnecessary.

The core insight: When you find yourself writing "for each element, search the rest of the array," that's a signal. Stop. Ask: "Can I store what I've already seen in a HashMap and look it up in O(1) instead?"

The transformation is always the same: instead of scanning backwards through elements you've already visited, you store them in a map as you go and look them up instantly.

JavaScriptO(n²) → O(n) transformation
// ❌ Brute force — nested loop — O(n²)
function twoSum_slow(nums, target) {
    for (let i = 0; i < nums.length; i++) {
        for (let j = i + 1; j < nums.length; j++) {
            // For each element, scan all others → O(n²)
            if (nums[i] + nums[j] === target) return [i, j];
        }
    }
}

// ✅ HashMap — single pass — O(n)
function twoSum_fast(nums, target) {
    const seen = new Map(); // stores: value → index

    for (let i = 0; i < nums.length; i++) {
        const complement = target - nums[i];
        // Instead of scanning: check the map in O(1)
        if (seen.has(complement)) {
            return [seen.get(complement), i];
        }
        seen.set(nums[i], i); // store: what have I seen so far?
    }
}
// The map replaces the inner loop. Same logic, O(n) instead of O(n²).

When to recognize this pattern:

Use Arrays + Hashing when the problem involves:

✓ "Find two elements that sum to X" (Two Sum family)
✓ "Find duplicates" (Contains Duplicate family)
✓ "Check if two strings are anagrams" (frequency counting)
✓ "Group elements by some property" (Group Anagrams)
✓ "Find the most frequent element" (frequency map)
✓ "Check if a string/array contains all elements of another" (subset check)
✓ Any time you need to look something up that you've already seen
Don't use this pattern when:

✗ Array is sorted → Binary Search or Two Pointers is likely better
✗ Problem involves contiguous subarrays with a condition → Sliding Window
✗ Space must be O(1) → Interviewer wants a different approach
✗ Order matters and you need to look ahead, not back → Two Pointers

HashMap in JavaScript — the three options:

JavaScriptMap vs Object vs Set — when to use each
// Map: best general-purpose, any key type, preserves insertion order
const map = new Map();
map.set('key', 1);          // O(1) set
map.get('key');              // O(1) get → 1
map.has('key');              // O(1) check → true
map.delete('key');           // O(1) delete
map.size;                     // length of map

// Object: fine when keys are strings (simpler syntax)
const freq = {};
freq['a'] = (freq['a'] || 0) + 1;  // count frequency

// Set: when you only need existence check, not a value
const seen = new Set();
seen.add(42);               // O(1)
seen.has(42);               // O(1) → true (no value needed)

// Rule of thumb:
// Need value?     → Map  (twoSum: store index)
// Need existence? → Set  (contains duplicate)
// Counting chars? → Object  (simpler syntax for string keys)
Section 02

The 5-Step Interview Framework

Exactly what to do and say from the moment the interviewer gives you a problem. Do this for every single problem — not just arrays + hashing.
Most freshers fail not because they can't code the solution, but because they jump straight to coding. Interviewers at Swiggy/PhonePe level test your process, not your speed. A slower thinker who explains clearly beats a fast coder who says nothing.
1
Understand — Ask clarifying questions
Before touching code or even thinking about the approach, ask questions. You need to understand the constraints. Every question you ask shows maturity. Never assume.

Ask: Input type/range (integers only? can be negative?), edge cases (empty array? single element?), return type (indices? values?), space constraints (must it be O(1) space?), duplicates (can there be duplicates?).
"Before I start — can the array be empty? Can elements be negative? Are there duplicate values? Should I return indices or values?"
2
Brute Force first — say it aloud, don't code it
Always identify the brute force solution first — even if you know the optimal. This shows you can reason from first principles. Mention why it's slow. Then say you'll optimize.

Never skip this step. It shows the interviewer you understand complexity tradeoffs.
"The naive approach is a nested loop — O(n²) time. For each element, I scan the rest to find its pair. That's too slow for large inputs. Let me optimize."
3
Explain your approach — before writing a single line
Describe your optimized solution in plain English. Draw the mental model. If using a HashMap, explain what you're storing as keys and what as values. Only start coding after the interviewer nods.

This is where most interviews are won or lost. A clear explanation means the interviewer can follow your code. Silence means they can't evaluate you.
"I'll use a HashMap to store elements I've already seen. As I iterate, I compute the complement I need. If the complement is in the map, I found the pair. One pass, O(n) time, O(n) space. Does that approach make sense before I code it?"
4
Code — while narrating every meaningful line
Write code top-to-bottom, narrating as you go. Don't code in silence. Skip narrating obvious things (variable declarations), but explain every non-obvious decision.

If you get stuck: don't freeze. Say "let me think through this" and reason aloud. An interviewer who hears your thinking can help you. Silence means they can't.
"I'm creating a Map... now iterating... computing the complement for this element... checking if I've seen it before... if yes, return the indices... if not, store the current element and keep going."
5
Verify — test with an example, state complexity, check edge cases
After coding: trace through a small example manually. State time and space complexity with reasoning. Then go through edge cases you identified in Step 1.

Don't wait for the interviewer to ask. Proactively say: "Let me verify this works and check edge cases."
"Let me trace through: nums=[2,7,11], target=9. i=0: complement=7, not in map, store {2:0}. i=1: complement=2, found in map at index 0, return [0,1]. ✓ Time: O(n) — one pass. Space: O(n) — map up to n entries. Edge case: empty array returns undefined — I should add a guard if needed."
When you get stuck mid-problem (it will happen):

✓ Say: "Let me think about this for a moment..." — then actually think aloud
✓ Say: "The brute force here would be... can I do better?"
✓ Say: "I'm not sure about this edge case — what should happen when...?"
✗ Never: sit in silence for more than 30 seconds
✗ Never: say "I don't know" and stop — always show your thinking process
✗ Never: start coding before explaining — this is the most common mistake

The Arrays + Hashing Template

Every arrays + hashing problem is a variation of one of these 4 templates. Memorize the skeleton — fill in the logic per problem.
JavaScriptTemplate 1 — Find pair with condition (Two Sum family)
function findPair(nums, target) {
    const seen = new Map(); // key: element value, value: index (or anything useful)

    for (let i = 0; i < nums.length; i++) {
        const complement = /* what you need */ target - nums[i];

        if (seen.has(complement)) {
            return [seen.get(complement), i]; // found! return what's needed
        }

        seen.set(nums[i], i); // store: element → its index
    }

    return []; // no pair found
}
// What changes per problem: complement formula, what you store, what you return
JavaScriptTemplate 2 — Detect duplicates / check membership
function hasDuplicate(nums) {
    const seen = new Set(); // Set when you only need existence, not a value

    for (const num of nums) {
        if (seen.has(num)) return true; // seen before → duplicate
        seen.add(num);
    }

    return false;
}
// What changes: the condition for "already seen", what to return
JavaScriptTemplate 3 — Frequency counting (anagram / most frequent)
function countFreq(s) {
    const freq = {}; // or new Map() — object is cleaner for char counting

    for (const ch of s) {
        freq[ch] = (freq[ch] || 0) + 1; // increment or initialize to 1
    }

    return freq;
}

// Compare two freq maps (for anagram check):
function isAnagram(s, t) {
    if (s.length !== t.length) return false; // early exit
    const freq = {};
    for (const ch of s) freq[ch] = (freq[ch] || 0) + 1;
    for (const ch of t) {
        if (!freq[ch]) return false; // char missing or count exhausted
        freq[ch]--;
    }
    return true;
}
JavaScriptTemplate 4 — Group by key (Group Anagrams family)
function groupBy(items) {
    const groups = new Map(); // key: canonical form, value: array of items

    for (const item of items) {
        const key = getKey(item); // derive a canonical key for the group

        if (!groups.has(key)) groups.set(key, []);
        groups.get(key).push(item);
    }

    return [...groups.values()]; // return grouped arrays
}
// What changes: getKey() function
// For anagrams: key = sorted string ("eat" → "aet")
// For same-length: key = item.length
// For same-sum: key = sum of digits

Problem 01 of 05 Easy
Two Sum
LeetCode #1 · leetcode.com/problems/two-sum
1
Problem: Given array nums and integer target. Return indices of two numbers that add to target. Exactly one solution guaranteed.
2
Brute force: Two nested loops. For each element at i, scan every element at j > i. Check if nums[i] + nums[j] === target. O(n²) time — too slow.
3
Key insight: For each element nums[i], I need to know if target - nums[i] exists in the array. Instead of scanning — store seen elements in a Map. Check in O(1).
4
Optimal plan: One pass. At each index: compute complement = target - nums[i]. If complement is already in the Map → return both indices. Else store nums[i] → i in the Map and continue.
5
Why single pass works: We only need to find the pair. When we're at index i, the complement's index (if it exists) was already stored during a previous iteration. We don't need to look ahead.
Interviewer
Given an array of integers and a target. Return indices of two numbers that add to the target.
You
Before I start — can there be negative numbers? Can the same element be used twice? Is there always exactly one answer?
Interviewer
Yes, negatives are possible. No, use each element once. Yes, exactly one answer.
You
The brute force is two nested loops — O(n²). For each element, check every other element. That'll work but is too slow. Let me think of something better.
You
If I'm at element X, I need to know if target - X exists anywhere earlier. Instead of scanning, I'll use a HashMap — store elements I've seen so far. At each step, compute the complement and look it up in O(1). One pass, O(n) total.
Interviewer
Good. What will you store in the map?
You
Key: the element's value. Value: its index. When I find the complement, I need to return both indices — so I need to know where the complement was.
Interviewer
Go ahead and code it.
You
[codes while narrating] Creating the map... iterating... complement is target minus current element... if map has it, return the complement's index and current index... else store current element and keep going.
You
Let me trace: nums=[2,7,11,15], target=9. i=0: comp=7, not in map, store {2:0}. i=1: comp=2, found at index 0. Return [0,1]. ✓ Time O(n), Space O(n).
Interviewer
What if there's no valid answer?
You
The problem guarantees exactly one answer, so this case won't occur. But defensively, the loop exits without returning — I could return an empty array or -1 as a signal.
JavaScriptTwo Sum — O(n) solution
/**
 * @param {number[]} nums
 * @param {number} target
 * @return {number[]}
 */
function twoSum(nums, target) {
    // Map: element value → index
    const seen = new Map();

    for (let i = 0; i < nums.length; i++) {
        const complement = target - nums[i];

        // Is the number I need already stored?
        if (seen.has(complement)) {
            return [seen.get(complement), i];
        }

        // Store current element so future iterations can find it
        seen.set(nums[i], i);
    }

    // Problem guarantees one answer, but handle gracefully
    return [];
}
Time: O(n) — one pass Space: O(n) — map stores up to n elements
  • Same element twice: e.g. [3,3], target=6. Works correctly — at i=1, complement=3, found at index 0 (stored in previous step). Returns [0,1].
  • Negative numbers: e.g. [-1, -2], target=-3. Works — complement = -3 - (-1) = -2, found at i=1. Map handles negative keys fine.
  • Array of length 2: Only one pair possible. Works — i=0 stores first element, i=1 finds complement.
  • Large values: JS Map handles any integer key. No overflow concern in JS (numbers are floats).
  • Multiple possible pairs: Problem guarantees one answer. If it didn't — we'd need to handle returning multiple or all pairs.
Problem 02 of 05 Easy
Contains Duplicate
LeetCode #217 · leetcode.com/problems/contains-duplicate
1
Problem: Return true if any value appears at least twice. Return false if all elements are distinct.
2
Brute force: Two loops, compare every pair. O(n²). Or sort the array and check adjacent elements — O(n log n). Both valid but not optimal.
3
Key insight: I don't need the index or any value associated with what I've seen — just existence. A Set is perfect here. As I iterate, if I've seen the element before, it's a duplicate. Otherwise add it and continue.
4
Shortcut: new Set(nums).size !== nums.length — if the set has fewer elements than the array, there were duplicates. One-liner but slightly less efficient (builds entire set even after finding first duplicate).
Interviewer
Given an integer array, return true if any value appears at least twice.
You
Can the array be empty? What should I return in that case?
Interviewer
Array will have at least 1 element.
You
I can think of three approaches. Brute force: compare every pair — O(n²). Sort and check adjacents — O(n log n). Or use a Set for O(n) time — I only need to know if I've seen something before, not its index, so a Set is ideal.
Interviewer
Go with the O(n) approach.
You
As I iterate, before adding each element to the Set, I check if it's already there. If yes — duplicate found, return true immediately. If I finish without finding one — return false. Early return is important here — no need to continue once we've found a duplicate.
JavaScriptContains Duplicate — O(n)
function containsDuplicate(nums) {
    const seen = new Set();

    for (const num of nums) {
        if (seen.has(num)) return true; // early return on first duplicate
        seen.add(num);
    }

    return false;
}

// One-liner alternative (slightly less efficient — no early exit):
// return new Set(nums).size !== nums.length;
Time: O(n) — one pass, early exit Space: O(n) — set stores up to n elements
  • Single element: [1] → Set gets 1, loop ends, return false. Correct — no duplicate.
  • All duplicates: [1,1,1] → At i=1, seen has 1, return true immediately. Efficient — doesn't scan rest.
  • Duplicate at end: [1,2,3,4,1] → All 4 stored, at i=4 sees 1 in set, returns true.
  • The one-liner: Fine for interviews, but the loop with early exit is better for large arrays — stops as soon as duplicate found.
Problem 03 of 05 Easy
Valid Anagram
LeetCode #242 · leetcode.com/problems/valid-anagram
1
Problem: Given strings s and t, return true if t is an anagram of s. An anagram uses the same characters the same number of times, in any order.
2
Brute force / simple: Sort both strings and compare — s.split('').sort().join('') === t.split('').sort().join(''). O(n log n) due to sorting. Valid, but O(n) is possible.
3
Key insight: Two strings are anagrams if and only if they have the same character frequency map. Count chars in s, then subtract counts using t. If any count goes negative or chars from t are absent → not an anagram.
4
Optimal plan: Build frequency map for s. Iterate t: for each char, if absent or count is 0 → return false. Decrement count. After both loops, all counts are 0 if truly an anagram — but we don't need a final check since we verified during iteration.
5
Early exit: If s.length !== t.length, they can't be anagrams. Return false immediately — saves time.
Interviewer
Check if two strings are anagrams.
You
Just lowercase letters? Or Unicode characters too?
Interviewer
Lowercase English letters only.
You
First quick win: if lengths differ, immediately return false — can't be an anagram. Otherwise, I need to verify both have the exact same character counts. I'll build a frequency map from s, then subtract using t. If any char is missing or goes to zero before we expect — not an anagram.
Interviewer
Could you also sort both strings?
You
Yes — sort both and compare. O(n log n). The HashMap approach is O(n) — one pass for each string. For large strings, that's meaningfully faster. I'll go with HashMap unless you want the simpler sorting version.
JavaScriptValid Anagram — O(n)
function isAnagram(s, t) {
    // Early exit: lengths must match
    if (s.length !== t.length) return false;

    const freq = {};

    // Build frequency map from s
    for (const ch of s) {
        freq[ch] = (freq[ch] || 0) + 1;
    }

    // Subtract using t — if char missing or overused → false
    for (const ch of t) {
        if (!freq[ch]) return false; // missing or count is 0
        freq[ch]--;
    }

    return true;
}

// Alternative — sorting (O(n log n), easier to remember):
// return s.split('').sort().join('') === t.split('').sort().join('');
Time: O(n) — two single passes Space: O(1) — at most 26 chars (lowercase only)
  • Same string: "abc", "abc" → same frequency → true.
  • Extra chars in t: "ab", "abc" → length check catches this → false.
  • Different char, same length: "ab", "cd" → freq['c'] is undefined → !freq['c'] is true → return false.
  • Space is O(1) not O(n): The freq object only has at most 26 keys (lowercase letters) — constant, not proportional to input size. Know this distinction — interviewers ask.
  • Unicode follow-up: If chars can be Unicode, change to new Map(). Object keys are coerced to strings — might cause issues with some Unicode. Map handles any key type.
Problem 04 of 05 Medium
Group Anagrams
LeetCode #49 · leetcode.com/problems/group-anagrams
1
Problem: Given array of strings, group anagrams together. Return list of groups. Order doesn't matter.
2
Key insight: All anagrams of a word have the same letters in sorted order. "eat", "tea", "ate" all sort to "aet". This sorted string is the canonical key for the group.
3
Plan: Use Template 4 (Group By). For each word: sort its characters → use as Map key. Push the word into that group. Return all Map values.
4
Why Map not Object: Keys can be any string. A regular object would work too, but Map is more idiomatic for this use case and slightly safer for unusual key values.
5
Time complexity: For each of the n strings, sorting it takes O(k log k) where k is the string's length. Total: O(n × k log k). HashMap operations are O(k) for string key hashing. Overall O(nk log k).
Interviewer
Group anagrams from an array of strings.
You
Can strings be empty? Can the array be empty? Are strings lowercase only?
Interviewer
Strings consist of lowercase letters. Array has at least one element.
You
The key observation: anagrams are the same word rearranged, so they all have the same characters. If I sort each string's characters, all anagrams in a group will produce the same sorted string. That sorted string is my canonical key.
You
I'll use a HashMap: key is the sorted word, value is an array of words that sort to that key. At the end, return all the map's values.
Interviewer
What's the time complexity?
You
For each of n words, sorting takes O(k log k) where k is the word length. So total is O(n × k log k). Space is O(n × k) for storing all strings in the map.
Interviewer
Can you do it without sorting each string?
You
Yes — instead of sorted string, use a character frequency array of length 26 as the key. For "eat": [1,0,0,0,1,0,...,1,...] (a=1, e=1, t=1). Join with a separator like "#" for the key string. That's O(k) per word instead of O(k log k). Total O(nk). Want me to code that version?
JavaScriptGroup Anagrams — sorted key approach
function groupAnagrams(strs) {
    const groups = new Map(); // sorted-word → [original words]

    for (const word of strs) {
        // Canonical key: sorted characters of the word
        const key = word.split('').sort().join('');

        if (!groups.has(key)) groups.set(key, []);
        groups.get(key).push(word);
    }

    return [...groups.values()];
}

// Optimized version — O(n*k) using frequency array key
function groupAnagramsFast(strs) {
    const groups = new Map();

    for (const word of strs) {
        const count = new Array(26).fill(0);
        for (const ch of word) {
            count[ch.charCodeAt(0) - 'a'.charCodeAt(0)]++;
        }
        const key = count.join('#'); // unique key per frequency profile

        if (!groups.has(key)) groups.set(key, []);
        groups.get(key).push(word);
    }

    return [...groups.values()];
}
Time: O(n·k·log k) sorted / O(n·k) freq array Space: O(n·k) — storing all strings
  • Single-char strings: ["a","b","a"] → "a" and "a" group together, "b" is alone. Works correctly.
  • All same anagram: ["abc","bca","cab"] → all map to "abc" → one group of 3.
  • No anagrams: ["abc","def"] → two groups of one each.
  • Empty string: [""] → sorts to "", groups into one. Multiple ["",""] → grouped together.
  • Why '#' separator in freq key: Without it, [1,11] and [11,1] might produce same string. With '#': "1#11#" vs "11#1#" — unique.
Problem 05 of 05 Medium
Top K Frequent Elements
LeetCode #347 · leetcode.com/problems/top-k-frequent-elements
1
Problem: Given array nums and integer k, return the k most frequent elements. Answer is guaranteed to be unique. Order doesn't matter.
2
Obvious approach: Build frequency map. Sort entries by frequency descending. Take first k. O(n log n) due to sorting.
3
Key insight — Bucket Sort: The maximum frequency any element can have is n (appears every time). So frequencies range from 1 to n. Create an array of n+1 buckets, where index = frequency. Put each element in its frequency-bucket. Then iterate buckets from right (highest freq) to left, collecting elements until we have k.
4
Why this is O(n): Frequency map: O(n). Bucket array: size n+1, fill in O(n). Collect from end: O(n) worst case. Total O(n) — better than sorting. This is the answer interviewers at CRED/Razorpay level expect.
Interviewer
Return the k most frequent elements from an array.
You
Is k always valid — i.e., k is between 1 and the number of unique elements?
Interviewer
Yes. Guaranteed unique answer.
You
Step one — build a frequency map, count how many times each element appears. That's O(n). Then I need the top k by frequency. The obvious approach is sort by frequency — O(n log n). But I think we can do O(n) with bucket sort.
Interviewer
Explain bucket sort.
You
The maximum frequency is n — an element can appear at most n times. So I create an array of n+1 buckets where bucket[i] holds all elements that appear exactly i times. Fill it in O(n). Then iterate from the end (highest frequency) and collect until I have k elements. Each operation is O(n). Total O(n) time, O(n) space.
Interviewer
When would you use a heap instead?
You
If k is much smaller than n and we want O(n log k) instead of O(n) space — a min-heap of size k works. Keep the k most frequent elements, evict the smallest when size exceeds k. But bucket sort is simpler here since k and n are both given.
JavaScriptTop K Frequent — O(n) bucket sort
function topKFrequent(nums, k) {
    // Step 1: frequency map
    const freq = new Map();
    for (const num of nums) {
        freq.set(num, (freq.get(num) || 0) + 1);
    }

    // Step 2: buckets[i] = elements with frequency i
    // Max possible frequency = nums.length
    const buckets = new Array(nums.length + 1).fill(null).map(() => []);

    for (const [num, count] of freq) {
        buckets[count].push(num);
    }

    // Step 3: collect from highest frequency bucket
    const result = [];
    for (let i = buckets.length - 1; i >= 1 && result.length < k; i--) {
        for (const num of buckets[i]) {
            result.push(num);
            if (result.length === k) break;
        }
    }

    return result;
}

// Simpler but O(n log n) — good to know as alternative:
// return [...freq.entries()]
//   .sort((a, b) => b[1] - a[1])
//   .slice(0, k)
//   .map(([num]) => num);
Time: O(n) — freq map + bucket fill + collect Space: O(n) — map + buckets
  • k = 1: Return just the most frequent element. Bucket scan stops after first non-empty bucket from the end.
  • All elements same frequency: e.g. [1,2,3], k=2. All in bucket[1]. Return first 2 encountered.
  • One element array: [5], k=1. freq={5:1}. buckets[1]=[5]. Return [5].
  • Multiple elements in one bucket: [1,1,2,2,3], k=2. Both 1 and 2 have freq=2. bucket[2]=[1,2]. Return [1,2]. Any order valid.
  • The heap alternative: O(n log k) time, O(n+k) space. Better if n is huge and k is tiny. Know both — interviewers follow up on this.

15 Interview Questions

Answer out loud before expanding. Mix of concept, trap, and pattern-recognition questions — exactly what Swiggy/PhonePe interviewers ask.
CoreWhen do you choose a HashMap over a brute-force nested loop?▼
When you find yourself writing "for each element, scan all others to find a matching partner" — that's the signal. A HashMap converts the inner scan from O(n) to O(1) lookup. The trade-off: O(n) extra space for the map. When the interviewer hasn't specified space constraints, this trade is almost always worth it. Pattern recognition: if the problem involves "find X that satisfies condition with another element", "check if Y has been seen before", or "count occurrences" — HashMap is your first thought.
TrapWhat is the difference between Map and Object in JavaScript for this pattern?▼
Object: Keys are always strings (or Symbols). Numbers are coerced to strings: {1: "a"} stores key "1", not 1. Fast, simple syntax. Fine for string and char counting. Map: Keys can be any type — numbers, objects, arrays, etc. Preserves insertion order. Slightly more syntax overhead. Better for non-string keys or when you need .size, .entries(), .keys(). For this pattern: use Object for character/string frequency counting (simpler). Use Map when keys are numbers or when you need Map-specific methods. Common mistake: using Object and expecting number keys — {1:"a"}[1] works, but Object.keys({1:"a"}) returns ["1"] (string) which can cause subtle bugs.
InterviewWalk me through your approach when you get a Two Sum variant you've never seen before.▼
Step 1: Identify it's a "find pair" problem. Step 2: Define the complement — what's the value I need to find given the current element? In Two Sum: target - nums[i]. In other variants: it might be target / nums[i], or target XOR nums[i], etc. Step 3: Can I compute this complement and look it up in O(1)? If yes, HashMap. Step 4: What do I store as value in the map? Depends on what the problem asks — index, frequency, count of pairs, etc. Step 5: Code Template 1 with the new complement formula. Most "find pair" variants are solved this way — the only thing that changes is the complement formula and what you store/return.
CoreWhat is the time and space complexity of building a frequency map?▼
Time: O(n) — one pass through the input, O(1) Map operations per element. Space: O(k) where k is the number of distinct elements. For an array of n integers: worst case O(n) (all unique). For lowercase English characters: O(26) = O(1) — the map never has more than 26 entries regardless of input size. This distinction matters in interviews: "Valid Anagram with only lowercase letters is O(1) space, not O(n)." Always mention the distinction between k (distinct elements) and n (input size) when analyzing space.
TrapIn Two Sum, why do you check the map BEFORE inserting the current element?▼
The problem says you cannot use the same element twice. If you insert first, then check — you might find the element you just inserted as the complement of itself. Example: nums=[3,3], target=6. If you insert nums[0]=3 first, then check complement=3 for nums[0] — you'd return [0,0] (same index twice). By checking first, then inserting: at i=0, complement=3 not in map (map is empty), so insert {3:0}. At i=1, complement=3 IS in map at index 0 ≠ 1, so return [0,1]. Correct. This order also means you're only looking at elements you've already visited — no need to look ahead.
InterviewWhat are 3 different ways to solve "Contains Duplicate"? Which would you code first in an interview?▼
1. Brute force: Two nested loops, compare each pair. O(n²) time, O(1) space. Say this exists, don't code it. 2. Sort: Sort array, check adjacent elements. O(n log n) time, O(1) or O(log n) space (sorting). Simple, worth mentioning. 3. Set (optimal): O(n) time, O(n) space. Add elements to Set as you go; if already present, return true. Code this one. In an interview: mention all 3, explain the trade-offs (space vs time), then code option 3. The one-liner return new Set(nums).size !== nums.length is fine to mention as an alternative, but the loop with early exit is better because it stops as soon as a duplicate is found.
CoreWhat is bucket sort? When does it apply in this pattern?▼
Bucket sort: when values fall within a known, bounded range [0, max], create an array of buckets where index = value. Place each element in its bucket. Read results in order. O(n + max) time, O(max) space. In arrays+hashing: frequency values are bounded by n (an element appears at most n times). So instead of sorting by frequency (O(n log n)), create n+1 frequency buckets (O(n)), place elements, read from highest bucket. Result: O(n) for Top K Frequent Elements instead of O(n log n). Know when to suggest it: "If frequency is bounded and we can use O(n) extra space, bucket sort beats comparison-based sorting."
InterviewHow do you handle the follow-up: "Can you solve it in O(1) space?"▼
This is a constraint change — you can't use a HashMap anymore. Now think about what other structural properties can help. For sorted arrays: Two Pointers (no extra space). For finding missing number: math (sum formula n*(n+1)/2 - actual sum = missing). For contains duplicate with extra constraint (duplicates within k positions): sliding window with Set of size k (O(k) space, which may qualify as "O(1)" if k is constant). For anagram: sort both strings (O(1) extra space, O(n log n) time). The key is: O(1) space usually means you exploit structure of the data (sorted order, math relationships, modifying input in-place) rather than storing seen elements. Always ask: "Is the array sorted, or can I sort it?" before agreeing that O(n) space is necessary.
TrapWhy does the one-liner `new Set(nums).size !== nums.length` have a downside?▼
It builds the entire Set even if the first two elements are duplicates. There's no early exit. If the array is [1, 1, 2, 3, 4, ... 10000 elements], the one-liner still processes all 10000 elements to find what was obvious after element 2. The loop with early return is O(n) worst case but terminates early when the duplicate is found — much better for large arrays with early duplicates. In an interview: mention the one-liner as a clean alternative, but explain this trade-off and code the loop version with early exit. This shows you think about performance at scale, not just correctness.
CoreWhat is the "canonical key" trick and where does it apply?▼
A canonical key is a normalized representation of a value that's the same for all items in the same "equivalence class". Used in Group By pattern (Template 4). Examples: Anagram grouping → sorted string ("eat","tea","ate" all become "aet"). Same digit sum → sum of digits. Same character frequency → frequency array joined with separator. Same XOR → XOR value. Same modulo → value % k. The trick: you need to map different representations of the "same thing" to a single key for grouping. Whatever property makes them equivalent becomes the key. In interviews: when asked "group these by some property," the question becomes "what is the canonical key that identifies each group?"
InterviewHow would you find the longest consecutive sequence? (LeetCode #128)▼
Problem: find the length of the longest consecutive sequence (e.g., [100,4,200,1,3,2] → 4 because [1,2,3,4]). Brute: O(n²) or O(n log n) with sorting. Optimal O(n) with Set: Put all numbers in a Set. For each number n, check if n-1 is in the Set. If n-1 is NOT there, n is a sequence start. From a start, count how long the consecutive sequence goes by checking n+1, n+2, etc. Why check for n-1: you only start counting from the beginning of a sequence — avoids counting the same sequence multiple times. Key insight: by only starting from sequence beginnings (elements with no left neighbor), each element is visited at most twice — O(n) total.
TrapWhat is a prefix sum and when does it combine with hashing?▼
Prefix sum: running cumulative sum where prefix[i] = sum of elements from index 0 to i. Sum of subarray [i+1..j] = prefix[j] - prefix[i]. Combined with HashMap: to find if a subarray sums to k, you need prefix[j] - prefix[i] = k, i.e., prefix[j] - k = prefix[i]. Store prefix sums seen so far in a Map. For each prefix sum, check if prefix - k exists in the map. This is the Two Sum pattern applied to prefix sums — O(n) for Subarray Sum Equals K (#560). Classic problem that looks hard but is O(n) once you recognize this. Pattern: "subarray with sum/count condition" → prefix sum + HashMap.
InterviewHow do you approach a problem you've never seen before but suspect involves hashing?▼
Say this out loud: "I'm going to ask what I'm looking for and what I've seen so far." If "what I've seen" is relevant to finding "what I'm looking for," hashing is the tool. Process: 1. Read problem slowly. Identify what you're searching for and what information from earlier elements is needed. 2. If the answer at each step depends on previously seen elements → HashMap stores those elements. 3. Define the key (what you look up) and value (what you need when you find it). 4. Choose Map/Set/Object based on whether you need a value or just existence. 5. Code Template 1, 2, 3, or 4 with the specific logic filled in. The templates don't change — only the formulas inside change. Recognize the pattern, slot in the formula, code it.
CoreExplain the time complexity of Group Anagrams carefully.▼
Let n = number of words. Let k = maximum length of a word. For each word: sorting it is O(k log k). Hashing the sorted string as a Map key is O(k) (need to hash all k chars). So per word: O(k log k). For all n words: O(n × k log k). Total time: O(nk log k). Space: O(nk) — storing all original strings in the map's arrays. The optimized frequency-array key approach: for each word, build a 26-element array in O(k), join it in O(26) = O(1). Per word: O(k). Total: O(nk) — better by log k factor. The distinction between O(nk log k) and O(nk) is the answer to "can you optimize Group Anagrams?" — shows depth that impresses interviewers.
InterviewWhat would you say if stuck on an arrays+hashing problem?▼
Never go silent. Say: "Let me think about what information from earlier elements I need right now." Then: "The brute force scans the array again for each element — O(n²). The question is what I'd be scanning for." Then identify the complement formula. If still stuck: "Can I work through a small example and see what pattern emerges?" Walk through [2,7,11,15], target=9. At element 7 — I need 2. Where is 2? I saw it at index 0. How would I know without scanning? I'd have stored it. That's the HashMap insight. Getting yourself unstuck by working an example aloud is a legitimate interview technique. Interviewers want to see your thinking process — not just the answer.
