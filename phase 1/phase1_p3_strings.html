Section 01

Strings Are Arrays — With Caveats

What makes string problems different from array problems, and the fundamental operations you must know cold.

A string is a sequence of characters. Almost every string technique you'll use is from Parts 0–2: HashMap for frequency counting, Two Pointers for palindrome checks, Sliding Window for substring problems. What's unique to strings: immutability, char arithmetic, and pattern matching algorithms.

The most important string fact for interviews: Strings are immutable in JavaScript and Java. Concatenating strings in a loop is O(n²) — each concatenation creates a new string. Always use an array and join at the end, or use a StringBuilder in Java. This is a performance trap that immediately signals experience level to interviewers.
JavaScriptString immutability — the O(n²) trap
// ❌ WRONG — O(n²): each concatenation creates a new string
function buildString_slow(chars) {
    let result = "";
    for (const ch of chars) {
        result += ch; // new string allocated each time → O(n²) total
    }
    return result;
}

// ✅ CORRECT — O(n): build array, join once at end
function buildString_fast(chars) {
    const parts = [];
    for (const ch of chars) {
        parts.push(ch);
    }
    return parts.join(""); // single allocation at the end
}

// Also fine for small strings (most interview problems):
const reversed = s.split("").reverse().join("");

// In Java: use StringBuilder
// StringBuilder sb = new StringBuilder();
// sb.append(ch);  // O(1) amortized
// return sb.toString();  // O(n) once at the end

Section 02

6 Core String Techniques

Every string problem uses one (or a combination) of these 6 techniques. Identify the technique first, then code it.
Technique 01
Two Pointers
L from start, R from end. Compare characters, skip non-alphanumeric, detect palindromes. Same as Part 1 — strings are just char arrays.
Palindrome check · Reverse words in place · Matching brackets from outside
Technique 02
Sliding Window
Window of chars, track state (freq map, distinct count). Part 2 pattern applied to strings. Longest/shortest substring with condition.
Longest no-repeat · Min window substring · Find all anagrams
Technique 03
Frequency Map
Count character occurrences. Compare two freq maps for anagram/permutation check. Use 26-element array for lowercase-only. Use Map for arbitrary chars.
Anagram check · Permutation check · Most/least frequent char · Ransom note
Technique 04
Stack-based
Push and pop characters based on rules. Classic for matching brackets, removing adjacent duplicates, decoding patterns, building result incrementally.
Valid parentheses · Remove adjacent duplicates · Decode string · Simplify path
Technique 05
String Building
Construct result incrementally using array + join. Reverse, rotate, split on delimiter, parse tokens. The "build the answer" approach for transformation problems.
Reverse words · Compress string · Zigzag conversion · Integer to Roman
Technique 06
Pattern Matching (KMP)
Find if pattern p exists in string s. Brute force O(nm). KMP runs in O(n+m) using a failure function. Know the concept and be able to explain it — coding KMP from scratch is rare but explaining it is not.
Find needle in haystack · Repeated substring pattern · String rotation check
How to identify which technique:

"Is it a palindrome?" → Two Pointers
"Longest/shortest substring with condition?" → Sliding Window
"Are these two strings anagrams?" → Frequency Map
"Matching brackets / decode / remove duplicates?" → Stack
"Reverse, rotate, reformat, compress?" → String Building
"Does this pattern appear inside this string?" → KMP or indexOf

JavaScriptKMP — Pattern Matching Algorithm (know for Hard problems)
// KMP: find all occurrences of pattern in text — O(n + m)
// Step 1: Build failure function (LPS array)
// LPS[i] = length of longest proper prefix of pattern[0..i] that is also a suffix
function buildLPS(pattern) {
    const lps = new Array(pattern.length).fill(0);
    let len = 0, i = 1;

    while (i < pattern.length) {
        if (pattern[i] === pattern[len]) {
            lps[i++] = ++len;
        } else if (len !== 0) {
            len = lps[len - 1]; // fall back, don't increment i
        } else {
            lps[i++] = 0;
        }
    }
    return lps;
}

// Step 2: Use LPS to search
function kmpSearch(text, pattern) {
    const lps = buildLPS(pattern);
    const result = [];
    let i = 0, j = 0; // i = text pointer, j = pattern pointer

    while (i < text.length) {
        if (text[i] === pattern[j]) {
            i++; j++;
        }
        if (j === pattern.length) {
            result.push(i - j); // found at index i - j
            j = lps[j - 1];       // use LPS to continue searching
        } else if (i < text.length && text[i] !== pattern[j]) {
            if (j !== 0) j = lps[j - 1]; // fall back using LPS
            else i++;                        // no fallback possible
        }
    }
    return result;
}
// In interviews: explain concept, code if asked. Most pattern matching
// problems accept indexOf (O(nm)) at the Easy/Medium level.
Section 04

Interview Framework for String Problems

What to say, ask, and think about before writing code.
1
Ask about charset and case
Always clarify: lowercase only? Uppercase? ASCII (128 chars)? Unicode (any char)? Numbers? Spaces? This determines whether to use a 26-element array (lowercase only, O(1) space) vs a Map (arbitrary chars). Also: case-sensitive or not?
"Is it only lowercase English letters, or can there be uppercase, numbers, or special characters? Is the comparison case-sensitive?"
2
Identify the technique from the problem type
Map the problem type to the technique: palindrome → Two Pointers. Anagram → Frequency Map. Substring condition → Sliding Window. Brackets/decode → Stack. Reverse/compress → String Building. Pattern in text → KMP or indexOf. Say the technique name before coding.
"This is an anagram check — I'll use a frequency array. Since it's lowercase letters only, I need 26 slots. Count characters in s, subtract characters in t. If all counts are 0 at the end, they're anagrams."
3
Decide: array or Map for frequency counting
Lowercase letters only → 26-element int array. Faster, O(1) space (fixed size). Any ASCII → 128-element array or Map. Unicode/arbitrary → Map only. Be explicit: "Since the problem says lowercase only, I'll use a 26-element array indexed by char code minus 'a'."
"For lowercase letters, I'll use an array of size 26 — freq[ch.charCodeAt(0) - 97]. This gives O(1) space since it never grows beyond 26 entries, regardless of input size."
4
Handle string mutability explicitly
If you need to modify the string (reverse, replace, swap), convert to array first. If you're building a result character by character, use an array and join at the end — never concatenate in a loop. Mention this proactively.
"Strings are immutable in JavaScript, so I'll convert to a char array with split(''), perform the operation, then join back. This avoids the O(n²) concatenation trap."
5
Edge cases: empty string, single char, all same
Always mention before coding: empty string → return 0/""/false? Single character → always a palindrome. All same characters → affects anagram, frequency, sliding window logic. String length 1 vs 0. Mention these proactively.
"Edge cases: empty string returns 0. Single character is always a palindrome. I'll add a length check at the top — if lengths differ for anagram check, immediately return false."

Problem 01 of 05Medium
Longest Palindromic Substring
LeetCode #5 · leetcode.com/problems/longest-palindromic-substring
1
Problem: Find the longest palindromic substring in s. A palindrome reads the same forwards and backwards.
2
Brute force: Check every substring — O(n³). For each of O(n²) substrings, palindrome check is O(n). Too slow.
3
Expand Around Center: A palindrome has a center. Expand outward from each possible center, checking if characters match. There are 2n-1 centers: n single characters (odd-length palindromes) and n-1 gaps between characters (even-length palindromes). O(n) centers × O(n) expansion = O(n²) total. Much better.
4
For each center: Start with L=center, R=center (odd) or L=center, R=center+1 (even). While L >= 0 and R < n and s[L] === s[R], expand: L--, R++. When done, the palindrome was s[L+1..R-1]. Track the longest.
5
Manacher's Algorithm solves this in O(n) but is complex. Interviewers almost never expect it — Expand Around Center is the expected answer at Medium level.
Interviewer
Find the longest palindromic substring.
You
Can the string be empty? And is there always at least one palindrome?
Interviewer
Non-empty string. Single characters are palindromes.
You
Brute force: check every substring — O(n³). I can do O(n²) with expand-around-center. Every palindrome has a center — either a single character for odd length, or a gap between two characters for even length. I expand outward from each center, comparing characters until they don't match. O(n) centers, O(n) expansion each = O(n²) total. O(1) space.
Interviewer
How do you handle even-length palindromes like "abba"?
You
"abba" has its center between the two b's. I handle this by trying two center types for each position i: single character (L=i, R=i for odd-length) and gap between i and i+1 (L=i, R=i+1 for even-length). I run expand-around-center for both and take the longer result.
Interviewer
Is there an O(n) solution?
You
Yes — Manacher's algorithm uses the symmetry of palindromes to avoid redundant expansion. It's O(n) time and space. It's complex to implement correctly in an interview setting. I'd use expand-around-center for this problem — O(n²) is usually sufficient. If you want, I can explain Manacher's concept without coding it.
JavaScriptLongest Palindromic Substring — O(n²), O(1) space
function longestPalindrome(s) {
    let start = 0, maxLen = 1;

    function expand(L, R) {
        // Expand outward while characters match
        while (L >= 0 && R < s.length && s[L] === s[R]) {
            if (R - L + 1 > maxLen) {
                maxLen = R - L + 1;
                start = L;
            }
            L--; R++;
        }
    }

    for (let i = 0; i < s.length; i++) {
        expand(i, i);     // odd-length palindromes  (center at i)
        expand(i, i + 1); // even-length palindromes (center between i and i+1)
    }

    return s.substring(start, start + maxLen);
}

// Example: s = "babad"
// i=0: expand('b','b') → "b" (len 1). expand('b','a') → no match
// i=1: expand('a','a') → "a", "bab" (len 3, start=0)
// i=2: expand('b','b') → "b", "aba" (len 3, start=1)
// Result: "bab" (first found of length 3)
Time: O(n²) — n centers × O(n) expansion Space: O(1) — just start and maxLen variables
  • Single char "a": expand(0,0) → "a" (len 1). expand(0,1) → R out of bounds, no expansion. Return "a".
  • All same "aaaa": Center at i=1, expand finds "aaaa". Returns "aaaa".
  • Even palindrome "abba": At i=1: expand(1,2) → s[1]='b'=s[2]='b', expand to s[0]='a'=s[3]='a'. Found "abba" len 4. Return "abba".
  • Two equal substrings "babad": "bab" and "aba" both have length 3. Return whichever is found first. The problem says any valid answer is acceptable.
  • Why start at maxLen=1: Single characters are always palindromes. Initialize to 1 so the worst case is returning s[0] (single char).
Problem 02 of 05Easy
Valid Parentheses
LeetCode #20 · leetcode.com/problems/valid-parentheses
1
Problem: Given string of '(', ')', '{', '}', '[', ']', determine if it's valid. Valid means every open bracket has a matching close bracket in the correct order.
2
Stack technique: Push open brackets. When seeing a close bracket, check if stack top is the matching open bracket. If yes, pop. If no, invalid. At the end, stack must be empty (all brackets matched).
3
Matching map: Use a Map or object to store close → open pairs: {')'→'(', '}'→'{', ']'→'['}. Clean and extendable.
4
Why stack: Brackets are LIFO — the most recently opened bracket must be closed first. A stack naturally enforces this ordering. This is the textbook stack problem and the correct approach for any matching/nesting problem.
Interviewer
Check if a string of brackets is valid.
You
Only brackets, no other characters? And an empty string is valid?
Interviewer
Only brackets. Empty string is valid.
You
This is a stack problem. Brackets are LIFO — the last opened must be the first closed. I push open brackets onto a stack. When I see a closing bracket, I check the top of the stack for the matching opener. If it matches, pop and continue. If it doesn't match or the stack is empty, return false. If the stack is empty at the end, all brackets were matched.
Interviewer
What's the matching logic?
You
I use a Map: closing bracket → expected opening bracket. When I see ')' — the top must be '('. When I see '}' — must be '{'. When I see ']' — must be '['. If the top doesn't match, the string is invalid.
Interviewer
What if there's a closing bracket but the stack is empty?
You
Return false immediately — there's no matching opener. I check stack.length === 0 before accessing the top. Or I can just check: if the top of the stack doesn't match the expected opener (including when stack is empty, so top would be undefined), return false.
JavaScriptValid Parentheses — O(n) with stack
function isValid(s) {
    const stack = [];
    const match = {
        ')': '(',
        '}': '{',
        ']': '['
    };

    for (const ch of s) {
        if ('([{'.includes(ch)) {
            stack.push(ch);             // open bracket → push
        } else {
            // close bracket: top must be the matching opener
            if (stack.pop() !== match[ch]) return false;
        }
    }

    return stack.length === 0; // all opened brackets were closed
}

// Alternative: push expected closer instead of opener
// When seeing '(', push ')'. When seeing close bracket, pop and compare.
// Slightly cleaner logic, same complexity.
Time: O(n) — single pass Space: O(n) — stack up to n/2 in worst case (all opens)
  • Empty string "": Loop doesn't run, stack is empty, return true. Correct.
  • Single char "(": Push '(', loop ends. Stack has 1 element. Return false (unmatched).
  • Closing first ")(": ch=')'. Stack empty, pop() = undefined ≠ '('. Return false. Correct.
  • Wrong order "([)]": Push '(', push '['. ch=')': pop returns '[' ≠ '('. Return false. Correct.
  • Why stack.pop() when empty returns undefined: undefined !== match[ch] evaluates to true → return false. This elegantly handles the "empty stack but close bracket seen" case without an explicit check.
Problem 03 of 05Medium
Encode and Decode Strings
LeetCode #271 · leetcode.com/problems/encode-and-decode-strings
1
Problem: Design encode/decode functions for a list of strings. Encode joins them into one string; decode splits back. The challenge: strings can contain any character including your delimiter.
2
Why simple delimiters fail: If you use ',' or '#' as delimiter, what if a string contains that character? e.g. ["a,b", "c"] encoded as "a,b,c" can't be decoded unambiguously.
3
Length-prefixed encoding: Encode each string as length + '#' + string. The '#' is just a separator between the length number and the string content — it's not used as a delimiter between strings. Example: ["abc", "de"] → "3#abc2#de". Decode by reading the length number, then reading exactly that many characters.
4
Why this works for any string: We always know exactly how many characters to read for each string (from the prefix number). No ambiguity about where one string ends and another begins, even if the strings contain '#' or any other character.
Interviewer
Design encode and decode functions for a list of strings. Strings can contain any character.
You
The challenge is that strings can contain any character — so any delimiter I choose might appear in the strings themselves. A simple join/split won't work reliably.
You
I'll use length-prefix encoding. For each string, encode it as its length, a '#' separator, then the actual string. "#" here separates the length number from the content — it's not a delimiter between strings. "abc" becomes "3#abc". ["abc","de"] becomes "3#abc2#de".
Interviewer
How do you decode?
You
Scan from left. Find the '#' to get the length number. Then read exactly that many characters after '#'. That's one string. Advance the pointer past those characters. Repeat until the end. Since we know the exact length, no ambiguity — even if the string itself contains '#'.
Interviewer
What about strings with multi-digit lengths?
You
The length can be any number of digits — "100#[100 chars]". I scan until I hit '#' to get the full number, then parseInt. Works for any length.
JavaScriptEncode and Decode — length-prefix approach
function encode(strs) {
    // Format each string as: length + '#' + string
    return strs.map(s => `${s.length}#${s}`).join('');
}

function decode(str) {
    const result = [];
    let i = 0;

    while (i < str.length) {
        // Find the '#' that separates length from content
        let j = i;
        while (str[j] !== '#') j++;

        // Read the length
        const len = parseInt(str.substring(i, j));

        // Extract exactly 'len' characters after '#'
        result.push(str.substring(j + 1, j + 1 + len));

        // Advance pointer past this string
        i = j + 1 + len;
    }

    return result;
}

// encode(["abc", "d#e", ""]) → "3#abcd#d#e0#"
// decode("3#abcd#d#e0#") → ["abc", "d#e", ""]
// Note: "d#e" encoded as "4#d#e" — the content '#' is just a char
Time: O(n) encode, O(n) decode — n = total chars Space: O(n) — encoded string + result array
  • String containing '#': "d#e" → encoded as "4#d#e". Decoder reads length 4, takes next 4 chars "d#e" — wait, that's only 3. Actually "d#e" has length 3 → "3#d#e". Decodes: reads 3, takes "d#e". Correct.
  • Empty string "": Encoded as "0#". Decoder reads 0, substring(j+1, j+1) = "". Pushes "". Correct.
  • Empty list []: encode returns "". decode("") loop doesn't run. Returns []. Correct.
  • Single character strings: "a" → "1#a". Decode reads 1, takes "a". Works.
  • Why length+# not just #: "#" alone would be confused with a '#' inside the string. Using length first tells us where the real content starts regardless of what's in the string.
Problem 04 of 05Medium
Reverse Words in a String
LeetCode #151 · leetcode.com/problems/reverse-words-in-a-string
1
Problem: Given string with words separated by spaces (may have leading/trailing/multiple spaces). Return string with words in reversed order, single space between each word.
2
Easy approach (JS): Split on whitespace, filter empty strings, reverse array, join with single space. 4 operations, very clean. O(n) time.
3
O(1) space approach (follow-up): If working in-place on a char array: (1) Reverse the entire string. (2) Reverse each individual word. (3) Clean up extra spaces. This is the "triple reverse" trick — commonly asked as a follow-up.
4
The triple reverse insight: "the sky is blue" → reverse all: "eulb si yks eht" → reverse each word: "blue is sky the". Words are in reverse order and correctly spelled.
Interviewer
Reverse the words in a string. Words may be separated by multiple spaces.
You
So I need to strip leading/trailing spaces and reduce multiple spaces to one?
Interviewer
Yes. " the sky " should return "sky the".
You
In JavaScript, the clean approach: split on whitespace using a regex that handles multiple spaces, filter out empty strings from the array, reverse the array, and join with a single space. One line effectively: s.trim().split(/\s+/).reverse().join(' '). O(n) time and space.
Interviewer
Can you do it in O(1) extra space?
You
Yes — the triple reverse technique. Working on a char array: first reverse the entire array. Then reverse each individual word within it. Then clean up extra spaces. This gives words in reverse order with correct spelling, using only in-place operations. The key insight: reversing all twice (once globally, once per word) is a net rotation that reverses word order.
JavaScriptReverse Words — easy O(n) + O(1) follow-up
// ── Simple approach — O(n) time, O(n) space ──────────────────
function reverseWords(s) {
    // split(/\s+/) splits on one or more spaces, filter removes empty strings
    return s.trim().split(/\s+/).reverse().join(' ');
}

// ── O(1) extra space — triple reverse on char array ──────────
function reverseWords_inplace(s) {
    const arr = s.split('');
    const n = arr.length;

    // Helper: reverse arr[L..R] in place
    function reverse(arr, L, R) {
        while (L < R) {
            [arr[L], arr[R]] = [arr[R], arr[L]];
            L++; R--;
        }
    }

    // Step 1: reverse the entire array
    reverse(arr, 0, n - 1);

    // Step 2: reverse each word
    let start = 0;
    for (let i = 0; i <= n; i++) {
        if (i === n || arr[i] === ' ') {
            reverse(arr, start, i - 1);
            start = i + 1;
        }
    }

    // Step 3: clean extra spaces (fast/slow pointer)
    let slow = 0, inWord = false;
    for (let fast = 0; fast < n; fast++) {
        if (arr[fast] !== ' ') {
            if (inWord) arr[slow++] = arr[fast];
            else { inWord = true; arr[slow++] = arr[fast]; }
        } else if (inWord) {
            arr[slow++] = ' ';
            inWord = false;
        }
    }
    if (arr[slow - 1] === ' ') slow--; // trim trailing space

    return arr.slice(0, slow).join('');
}
Time: O(n) both versions Space: O(n) simple / O(1) extra for in-place
  • Multiple spaces " the sky ": Simple: split(/\s+/) handles multiple spaces, filter(Boolean) handles leading/trailing empty strings. Returns "sky the".
  • Single word "hello": Simple: trim() → "hello", split → ["hello"], reverse → ["hello"], join → "hello".
  • The /\s+/ regex: Matches one or more whitespace characters. Better than split(' ') which produces empty strings for multiple spaces.
  • When to code the O(1) version: The interviewer asks "can you do it with O(1) extra space?" It's a follow-up, not the primary solution. The simple version is always correct to code first.
Problem 05 of 05Medium
String to Integer (atoi)
LeetCode #8 · leetcode.com/problems/string-to-integer-atoi
1
Problem: Implement atoi (string to integer). Rules: skip leading whitespace, read optional sign (+/-), read digits until non-digit or end, clamp to 32-bit signed integer range [−2³¹, 2³¹−1].
2
Why this problem is asked: It tests methodical state handling and edge case awareness, not algorithm cleverness. Interviewers want to see you enumerate and handle all the edge cases correctly.
3
Step by step: (1) Trim leading whitespace. (2) Read sign if present. (3) Read digits, building the number: result = result * 10 + digit. (4) Stop at first non-digit. (5) Clamp to [−2³¹, 2³¹−1].
4
Integer overflow: In JS, numbers are 64-bit floats — no overflow during computation. But the problem requires clamping to 32-bit range. Check: if result > 2³¹-1 → return 2³¹-1. If result < -2³¹ → return -2³¹. Apply sign before clamping.
Interviewer
Implement string to integer. Handle edge cases.
You
Let me enumerate the edge cases first: leading whitespace, optional + or - sign, non-digit characters stopping the parsing, no digits at all returning 0, and overflow clamping to 32-bit signed range.
You
My approach: skip whitespace, read sign, then iterate reading digits until a non-digit is found. Build the number as result = result * 10 + digit. Apply sign, then clamp to [-2^31, 2^31-1].
Interviewer
What if there are no digits after the sign?
You
If we see a '+' or '-' but the next character isn't a digit, the number is 0. My digit loop simply won't execute, result stays 0, return 0. Cases like "+-12" or "++" — after reading the first sign, the next char is also a sign (not a digit), so the loop doesn't run. Return 0.
Interviewer
How do you detect overflow?
You
In JavaScript, numbers won't overflow — they're 64-bit floats. But the problem wants 32-bit signed integer behavior. I clamp AFTER computing the full number. INT_MAX = 2^31 - 1 = 2147483647. INT_MIN = -2^31 = -2147483648. If result * sign exceeds these bounds, return the bound.
JavaScriptString to Integer (atoi) — O(n)
function myAtoi(s) {
    const INT_MAX = 2147483647;   // 2^31 - 1
    const INT_MIN = -2147483648;  // -2^31

    let i = 0;

    // Step 1: skip leading whitespace
    while (i < s.length && s[i] === ' ') i++;

    // Step 2: read optional sign
    let sign = 1;
    if (i < s.length && (s[i] === '+' || s[i] === '-')) {
        if (s[i] === '-') sign = -1;
        i++;
    }

    // Step 3: read digits
    let result = 0;
    while (i < s.length && s[i] >= '0' && s[i] <= '9') {
        const digit = s[i].charCodeAt(0) - 48; // '0'.charCodeAt(0) = 48
        result = result * 10 + digit;
        i++;
    }

    // Step 4: apply sign and clamp
    result *= sign;
    if (result > INT_MAX) return INT_MAX;
    if (result < INT_MIN) return INT_MIN;
    return result;
}
Time: O(n) — single pass Space: O(1) — no extra data structures
  • "" empty string: Skip whitespace loop doesn't run. No sign. Digit loop doesn't run. Return 0.
  • " -42": Skip 3 spaces, sign = -1, read 42, result = 42 * -1 = -42. Return -42.
  • "4193 with words": Read 4193, hit ' ', stop. Return 4193. Non-digit stops parsing.
  • "words and 987": After skipping spaces, first char 'w' is not digit and not sign. Digit loop doesn't run. Return 0.
  • "21474836460" (overflow): Result builds up to 21474836460 > INT_MAX. Return INT_MAX = 2147483647.
  • "-91283472332" (underflow): Result = -91283472332 < INT_MIN. Return INT_MIN = -2147483648.
  • "+-12": Read '+', sign=1, i++. Next char is '-', not a digit. Digit loop doesn't run. Return 0.

Section 07

15 Interview Questions

Answer out loud first. These cover every angle that FAANG and product company interviewers probe on strings.
TrapWhy is string concatenation in a loop O(n²)? How do you fix it?▼
Strings in JavaScript (and Java, Python) are immutable. When you do result += ch, the runtime creates a brand new string of length result.length + 1, copies all existing characters, and adds the new character. For n concatenations: first copy costs 1 op, second 2, third 3... total = 1+2+...+n = O(n²). Fix: push characters into an array (O(1) per push), then join() once at the end (O(n) for the final join). In Java: use StringBuilder — it maintains an internal buffer and only copies when the buffer is full (amortized O(1) append). Saying this proactively in an interview shows you understand string immutability and production-level performance concerns.
CoreHow do you check if two strings are anagrams? What are the two approaches?▼
Approach 1 — Sort and compare: Sort both strings, compare. If equal, anagrams. O(n log n) time, O(n) space for sorted copies. Simple but slower. Approach 2 — Frequency map: Build frequency array/map for one string. Decrement for the other. If all counts are 0, they're anagrams. O(n) time. If only lowercase letters, O(1) space (26-element array). If arbitrary chars, O(k) space where k = number of distinct characters. Always use approach 2 in interviews — it's faster and shows you know the optimal solution. Early exit: if lengths differ, immediately return false (can't be anagrams).
AlgorithmExplain the Expand Around Center approach for palindromes. Why O(n²) and not O(n³)?▼
Brute force palindrome check: generate all O(n²) substrings, check each in O(n) → O(n³). Expand Around Center insight: every palindrome has a center. Odd-length palindromes have a single character center. Even-length have a gap center. There are 2n-1 centers total. For each center, expand outward — compare s[L] and s[R], if equal expand further. Expansion is O(n) per center in the worst case (entire string is a palindrome). But total expansion across all centers is also O(n) — each character is "visited" as a center once and as a boundary a bounded number of times. The naive analysis gives O(n²), and more careful analysis confirms this. Why not O(n³): we don't check every possible substring length from scratch — we expand incrementally and stop at the first mismatch. No wasted work.
InterviewWhat is Manacher's Algorithm? Do you need to code it?▼
Manacher's is an O(n) algorithm for finding all palindromic substrings simultaneously. Key idea: if there's a palindrome centered at C with right boundary R, any palindrome center within [C, R] has a mirror center on the left side of C. We can use the mirror's palindrome length as a starting point for the new expansion — no need to re-verify already-checked characters. This gives amortized O(1) per center → O(n) total. Do you need to code it? In an interview: No — almost never expected. Expand Around Center (O(n²)) is the expected answer for "Longest Palindromic Substring" at Medium level. What you should do: mention Manacher's exists when asked "can you do better than O(n²)?", explain the concept (mirror palindrome insight), and offer to code it if specifically asked. Saying "there's an O(n) solution called Manacher's, I can explain the concept" demonstrates knowledge without requiring you to memorize the complex implementation.
CoreWhy is a stack the right data structure for bracket matching?▼
Bracket matching is a LIFO (Last In, First Out) problem. The most recently opened bracket must be the first one closed. This is exactly what a stack models. When you open a bracket, push it. When you see a closing bracket, the bracket that should close is the most recently opened — the stack top. If the top matches, pop (it's been closed). If it doesn't match or the stack is empty, invalid. At the end, the stack must be empty (all brackets closed). Any data structure other than a stack would require scanning backwards to find the matching opener — O(n) per close bracket → O(n²). The stack gives O(1) access to the most recent opener. This principle generalizes: any "matching/nesting" problem where the inner scope must close before the outer scope → Stack.
InterviewHow do you decode an encoded string like "3[a2[bc]]" → "abcbcabcbc"?▼
LeetCode #394. Use a stack to handle nesting. Two stacks or a stack of pairs: one for current string, one for repeat count. Scan left to right: digit → build number. '[' → push (current string, current number) onto stack, reset current string and count. letter → append to current string. ']' → pop (prev_string, count) from stack. current = prev_string + current.repeat(count). Walk through "3[a2[bc]]": push ("", 3). Push ("a", 2). See 'b','c': current = "bc". See ']': pop ("a",2), current = "a" + "bc".repeat(2) = "abcbc". See ']': pop ("",3), current = "" + "abcbc".repeat(3) = "abcbcabcbc". Return "abcbcabcbc". O(n * output size) time where output can be exponentially large.
TrapWhat are the edge cases in string-to-integer (atoi) problems?▼
Enumerate all edge cases before coding atoi-style problems: (1) Leading whitespace — skip spaces only, not other chars. (2) Sign — optional '+' or '-'. Only one. After sign, must be digit or return 0. (3) Multiple signs "+-12" — read first sign, then next char is '-' (not digit) → return 0. (4) No digits " " or "abc" → return 0. (5) Digits followed by non-digits "4193 with words" → parse 4193, stop at space. (6) Overflow: number exceeds 32-bit signed range. Clamp to INT_MAX (2147483647) or INT_MIN (-2147483648). (7) All zeros "0000" → return 0. (8) Leading zeros "007" → return 7. The art is not the algorithm (it's just loop through digits) but correctly handling all these cases. Mentioning them all before coding is what impresses interviewers.
AlgorithmWhat is KMP? When would you use it over indexOf?▼
KMP (Knuth-Morris-Pratt): pattern matching in O(n+m) where n = text length, m = pattern length. Brute force is O(nm). KMP preprocesses the pattern to build an LPS (Longest Proper Prefix which is also Suffix) array — this tells us how far to "fall back" in the pattern when a mismatch occurs, avoiding re-comparison of characters we've already matched. Use KMP when: (1) The interviewer explicitly asks for O(n+m) matching. (2) The problem requires finding multiple non-overlapping occurrences efficiently. (3) The problem is "does s rotate to t" (check if t appears in s+s — use KMP for O(n)). In interviews: JavaScript's indexOf is O(nm) internally but usually fast enough for problem constraints. At Easy/Medium level, using indexOf is accepted. At Hard level or when asked for optimal complexity, know KMP. In practice (industry), you'd use built-in string methods — KMP is academic knowledge that shows depth.
InterviewHow do you check if one string is a rotation of another?▼
String s is a rotation of t if and only if s appears as a substring of t+t. Example: "abcde" rotated is "cdeab". t+t = "abcdeabcde". "cdeab" appears inside it. Why: concatenating t with itself creates all possible rotations as substrings. So: return s.length === t.length && (t+t).includes(s). O(n) with KMP, O(n²) with naive substring search. The includes/indexOf approach is O(n²) in the worst case but accepted in interviews. Key insight: t+t contains all rotations — this is an elegant trick worth knowing. If s and t have different lengths, they can't be rotations. Check that first.
CoreWhat is the difference between substring, subsequence, and subarray?▼
Subarray / Substring: contiguous elements from the original sequence. "abc" from "xabcx". Order preserved, no gaps. Two Pointers and Sliding Window work here because contiguity enables the "expand/shrink" logic. Subsequence: elements in order but not necessarily contiguous. "ac" from "abc". Can skip elements. DP (Dynamic Programming) is usually needed — can't use sliding window because there's no "invalid window" concept when elements can be skipped. Subset: any elements, any order. "ca" from "abc". For strings, this typically means character counts (anagram problems). This distinction matters: "longest substring without repeating characters" → sliding window. "longest common subsequence" → DP. "valid anagram" → frequency map (subset equality). Misidentifying which type the problem asks for leads to the wrong algorithm entirely.
TrapHow do you handle multiple spaces when splitting a string into words?▼
s.split(' ') on " hello world " produces ["", "", "hello", "", "", "world", "", ""] — empty strings for consecutive spaces and leading/trailing spaces. Two fixes: (1) s.trim().split(/\s+/) — trim removes leading/trailing spaces, /\s+/ splits on one or more whitespace characters. Produces ["hello", "world"]. (2) s.split(' ').filter(Boolean) — split(' ') and filter out empty strings. Produces the same result. For most interview problems: use s.trim().split(/\s+/) — it's the cleanest one-liner. Note: /\s+/ matches any whitespace including tabs and newlines, not just spaces. If the problem guarantees single-space separators, s.trim().split(' ') works fine. Always test with " hello world " mentally before submitting.
InterviewHow do you find the first non-repeating character?▼
LeetCode #387. Two passes: (1) Build frequency map — count each character's occurrences. (2) Iterate the string again in order — return the first character whose frequency is 1. O(n) time, O(k) space where k is charset size. Code: const freq = {}; for(const c of s) freq[c] = (freq[c]||0)+1; for(let i=0; i<s.length; i++) if(freq[s[i]]===1) return i; return -1. The two-pass approach preserves the original order — the second pass iterates in input order, guaranteeing "first" means leftmost. One-pass approach using ordered Map: in JavaScript, Map preserves insertion order, so you could do one pass building the map, then iterate map entries looking for count 1. Same O(n) — the two-pass approach is cleaner to explain.
AlgorithmExplain the "triple reverse" for reversing words in-place.▼
Triple reverse for in-place word reversal: (1) Reverse the entire string. (2) Reverse each individual word. (3) Clean up spaces. Why it works: "the sky is blue" → reverse all → "eulb si yks eht". Now words are in reverse order but each word's characters are also reversed. Fix each word: reverse each word individually → "blue is sky the". The two reversal operations cancel each other for within-word character order, but the word-level reversal remains. This uses O(1) extra space (in-place swaps). The clean version in JavaScript: split to char array, reverse whole array, find word boundaries and reverse each word, handle multiple spaces with fast/slow pointer. This is a classic follow-up question when you give the simple O(n) space answer — good to know the technique by name.
InterviewHow do you compress a string like "aaabbbcc" → "a3b3c2"?▼
LeetCode #443. Two-pointer: read with 'fast', write with 'slow'. For each group of same characters: count them (advance fast while fast and fast-1 are same). Write the character at slow position. If count > 1, write each digit of count as individual characters. Advance slow past written characters. Why write digits individually: "a123" needs 4 chars, count=123. JavaScript: convert to string and write each char. In-place modifies the original array, returns new length. Edge cases: single character groups ("a") — count is 1, don't write the "1" (LeetCode's constraint). Groups of exactly 10, 100 — multi-digit counts. The slow/fast approach gives O(n) time, O(1) extra space. A simpler O(n) space approach: build a new string with array and join — but the problem requires in-place.
CoreWhat's the space complexity difference between a 26-element array and a Map for character frequency?▼
26-element array: Always exactly 26 integers, regardless of input. O(1) space — fixed size. Only works for lowercase a-z. Index = charCode - 97. Fast — array indexing vs hash computation. Map (or object): O(k) space where k = number of distinct characters in the input. For a 26-char lowercase-only string, Map has at most 26 entries. For ASCII strings, at most 128 entries. For Unicode, could be much more. Both are O(1) in terms of dependence on input size n when charset is bounded. But interviewers appreciate the explicit distinction: "Since the problem constrains to lowercase letters only, I'll use a 26-element fixed array — O(1) space, no hash overhead." vs "Since the input can have any Unicode character, I'll use a Map — O(k) space where k is the number of distinct characters." Saying this shows you're thinking about both correctness and performance.
