Arrays + Hashing

The foundation of DSA. Almost every problem uses arrays. Hashing (Maps + Sets) turns O(n²) brute force solutions into O(n). Learn this first — everything else builds on it.

What to understand before solving problems
✓
Array fundamentals + time complexities
Access, search, insert, delete — which are O(1) vs O(n) and why
must
Exactly what to learn
  • Access by index: O(1) — memory is contiguous, just calculate offset
  • Search (unsorted): O(n) — must check every element
  • Insert at end: O(1) amortized (dynamic array). Insert at index: O(n) — must shift elements
  • Delete at end: O(1). Delete at index: O(n) — must shift elements
  • JS arrays are dynamic — no fixed size. JS Array methods to know: push/pop O(1), shift/unshift O(n), splice O(n), slice O(n), indexOf O(n), includes O(n), sort O(n log n)
  • Prefix sum: precompute running sum so range sum queries become O(1) after O(n) build
Core pattern: Prefix Sum
Prefix Sum — range sum in O(1)
// Build prefix sum array: O(n) once
function buildPrefix(nums) {
    const prefix = [0];  // prefix[0] = 0, prefix[i] = sum of nums[0..i-1]
    for (const n of nums) prefix.push(prefix.at(-1) + n);
    return prefix;
}

// Query sum of range [l, r] inclusive: O(1)
function rangeSum(prefix, l, r) {
    return prefix[r + 1] - prefix[l];
}

// Example: nums = [1,2,3,4,5]
// prefix =  [0,1,3,6,10,15]
// sum(1,3) = prefix[4] - prefix[1] = 10 - 1 = 9 ✓ (2+3+4)
Core pattern: HashMap for O(n) lookups
HashMap — trading space for time
// Brute force: find two numbers that sum to target — O(n²)
for (let i = 0; i < nums.length; i++)
    for (let j = i+1; j < nums.length; j++)
        if (nums[i] + nums[j] === target) return [i, j];

// Optimized: HashMap — O(n) time, O(n) space
function twoSum(nums, target) {
    const seen = new Map();  // value → index
    for (let i = 0; i < nums.length; i++) {
        const complement = target - nums[i];
        if (seen.has(complement)) return [seen.get(complement), i];
        seen.set(nums[i], i);
    }
}
// KEY INSIGHT: for every element, we ask "have I seen what I need?"
// instead of "what's the other element?" — this is the HashMap mindset

Kadane's Algorithm — must know
Maximum Subarray — Kadane's
function maxSubArray(nums) {
    let maxSum = nums[0], current = nums[0];
    for (let i = 1; i < nums.length; i++) {
        // At each step: extend current subarray OR start fresh from nums[i]
        current = Math.max(nums[i], current + nums[i]);
        maxSum = Math.max(maxSum, current);
    }
    return maxSum;
}
// Key insight: if extending makes it worse (current + nums[i] < nums[i]),
// restart from nums[i]. That's it — greedy decision at every step.

Two Pointers

Two pointers move toward each other (or at different speeds) to avoid nested loops. Turns O(n²) into O(n). Recognize it when: sorted array, find pair, shrink from both ends.

The 3 Two-Pointer setups
✓
Opposite-end pointers (left + right)
Sort array, start pointers at both ends, move based on sum comparison
must
Exactly what to learn
  • Setup: left = 0, right = n-1. Move left → if need larger sum. Move right ← if need smaller sum.
  • Prerequisite: array must be sorted (or sortable). Why? Sorted = predictable direction to move.
  • Works for: find pair with target sum, check palindrome, container with most water
  • When sum too small → move left right (increase). When sum too big → move right left (decrease)

3Sum #15MedFix one, two-pointer for remaining. Skip duplicates!
Container With Most Water #11MedMove the shorter side — greedy reasoning
Trapping Rain Water #42HardTrack max from left + right, water = min(maxL, maxR) - height
🔑 Signal: use opposite-end pointers when
Sorted (or sortable) array + find pair/triple with a sum condition + need O(n) solution. 3Sum pattern is the foundation of many interview problems.
✓
Fast + Slow pointers (Floyd's cycle)
Detect cycles, find middle, kth from end
must · linked list + array
Exactly what to learn
  • Slow moves 1 step, fast moves 2 steps. If cycle exists: they meet inside it.
  • Cycle detection: fast catches slow if cycle (they meet). If fast reaches null: no cycle.
  • Find middle: when fast reaches end, slow is at middle. (Fast = 2x speed = middle when done)
  • Kth from end: move fast K steps first, then both at same speed. When fast reaches end, slow is at kth from end.

Sliding Window

A contiguous subarray or substring that expands/shrinks dynamically. Avoids recomputing from scratch each time. Signal: "find subarray/substring with condition" → think sliding window.

Fixed window vs Variable window
✓
Fixed-size window
Window size k is given. Slide and maintain running state.
must
Pattern template
Fixed window template
function fixedWindow(nums, k) {
    let windowSum = 0, maxSum = -Infinity;

    // Build first window
    for (let i = 0; i < k; i++) windowSum += nums[i];
    maxSum = windowSum;

    // Slide: add right element, remove left element
    for (let right = k; right < nums.length; right++) {
        windowSum += nums[right] - nums[right - k];  // add new, drop old
        maxSum = Math.max(maxSum, windowSum);
    }
    return maxSum;
}

✓
Variable-size window (expand + shrink)
Expand right, shrink left when condition violated. Find longest/shortest valid window.
must · harder but more common
Pattern template
Variable window template
function variableWindow(s) {
    let left = 0, maxLen = 0;
    const window = new Map();  // track window state

    for (let right = 0; right < s.length; right++) {
        // 1. Expand: add s[right] to window
        window.set(s[right], (window.get(s[right]) || 0) + 1);

        // 2. Shrink: while window is INVALID, move left
        while (/* condition violated */ window.size > 2) {
            const c = s[left++];
            window.set(c, window.get(c) - 1);
            if (window.get(c) === 0) window.delete(c);
        }

        // 3. Window is now valid — record result
        maxLen = Math.max(maxLen, right - left + 1);
    }
    return maxLen;
}
// Same structure for almost ALL variable window problems
// Only the "condition" and "window state" change

Linked Lists

Nodes with next pointers. No index access (O(n) to find). But O(1) insert/delete at known position. The patterns: reversal, two pointers, merge. Draw the pointer operations before coding.

Must-know patterns
✓
LL basics + Reversal
Node structure, traversal, reverse iteratively and recursively
must
Exactly what to learn
  • Node structure: { val: number, next: Node | null }. Last node's next = null.
  • Iterative reversal: 3 pointers — prev, curr, next. Move forward, flip pointer backward.
  • Recursive reversal: base case (null or single node), recursive step flips one link
  • Reverse sublist (between positions L and R): find L, reverse next (R-L) nodes, reconnect
  • Critical rule: always draw the linked list and pointer movements before coding LL problems
Iterative reversal — must know cold
Reverse Linked List — iterative
function reverseList(head) {
    let prev = null, curr = head;

    while (curr) {
        const next = curr.next;  // save next before overwriting
        curr.next = prev;         // flip the pointer
        prev = curr;              // advance prev
        curr = next;              // advance curr
    }
    return prev;  // prev is new head
}
// Trace: 1→2→3→null  becomes  null←1←2←3 (prev=3, new head)

Stack = LIFO (last in first out). Queue = FIFO. The real interview magic: monotonic stack — solves "next greater element" type problems in O(n) that seem to need O(n²).

must
Exactly what to learn
  • Stack in JS: array with push/pop. Stack operations: push (add to top), pop (remove from top), peek (see top without removing)
  • When to use stack: matching brackets/parentheses, undo/redo, converting infix to postfix, iterative DFS

✓
Monotonic Stack
Next greater/smaller element in O(n). Decreasing stack = find next greater.
must · interview favorite
Exactly what to learn
  • Monotonic decreasing stack: elements in stack always decreasing from bottom to top
  • When new element is GREATER than top: pop top (we found its "next greater element"), keep popping until stack is empty or top is greater
  • Whatever remains in stack at the end has no next greater element
  • Monotonic increasing stack: same idea but for "next smaller element" problems
Monotonic stack template
Next Greater Element — monotonic decreasing stack
function nextGreaterElements(nums) {
    const result = new Array(nums.length).fill(-1);
    const stack = [];  // stores INDICES (not values)

    for (let i = 0; i < nums.length; i++) {
        // While current element is greater than top of stack
        while (stack.length && nums[i] > nums[stack.at(-1)]) {
            const idx = stack.pop();
            result[idx] = nums[i];  // found next greater for idx
        }
        stack.push(i);
    }
    return result;
    // Remaining indices in stack have no next greater → already -1
}

Binary Search

Binary search is not just for sorted arrays. The real pattern: whenever you can eliminate half the search space at each step → binary search. "Binary search on the answer" is the key insight many miss.

Two forms of binary search
✓
Classic binary search + sorted array variants
Find target, find leftmost/rightmost, search rotated array
must
The template — get this right first
Binary Search — the exact template to use
function binarySearch(nums, target) {
    let left = 0, right = nums.length - 1;

    while (left <= right) {  // ← <= not <
        const mid = left + Math.floor((right - left) / 2);  // avoid overflow

        if (nums[mid] === target) return mid;
        else if (nums[mid] < target) left = mid + 1;   // ← +1, not mid
        else right = mid - 1;                           // ← -1, not mid
    }
    return -1;  // not found
}
// Why left + (right-left)/2? Prevents integer overflow (irrelevant in JS
// but good habit and expected in interviews)

Template for "binary search on answer"
Binary Search on Answer template
// Example: Koko Eating Bananas — find minimum speed to eat all in h hours
function minEatingSpeed(piles, h) {
    let left = 1, right = Math.max(...piles);

    while (left < right) {  // ← < not <=  (looking for minimum valid)
        const mid = Math.floor((left + right) / 2);
        if (canFinish(piles, h, mid)) {
            right = mid;   // valid, try smaller (minimize)
        } else {
            left = mid + 1;  // too slow, need faster
        }
    }
    return left;
}

function canFinish(piles, h, speed) {
    let hours = 0;
    for (const pile of piles) hours += Math.ceil(pile / speed);
    return hours <= h;
}

Recursion + Backtracking

Recursion: solving a problem by solving smaller versions of itself. Backtracking: try a choice → recurse → undo the choice (backtrack) → try next choice. Used for: all combinations/permutations/subsets problems.

Recursion fundamentals first
✓
Recursion basics — base case + recursive case
Call stack, how recursion works in memory, tail recursion
must · foundation
Exactly what to learn
  • Base case: the condition where recursion stops. Without it → infinite recursion → stack overflow.
  • Recursive case: call the same function with a smaller/simpler input that moves toward base case.
  • How call stack works: each recursive call adds a frame. Return unwinds frames. Stack depth = recursion depth.
  • For every recursive function: define (1) what does this function do? (2) base case (3) recursive step assuming function works correctly on smaller input
  • Fibonacci, factorial — trivial. Then move to harder: merge sort, tree traversal.

✓
Backtracking — Subsets, Permutations, Combinations
The universal backtracking template. All 3 patterns come from the same structure.
must
The universal backtracking template
Backtracking template — memorize this structure
function backtrack(candidates, start, currentPath, result) {
    // Base case / record result
    result.push([...currentPath]);  // spread — snapshot of current state

    for (let i = start; i < candidates.length; i++) {
        // Skip duplicates (when input has duplicates)
        if (i > start && candidates[i] === candidates[i-1]) continue;

        // 1. CHOOSE: add to path
        currentPath.push(candidates[i]);

        // 2. RECURSE: explore with this choice
        backtrack(candidates, i + 1, currentPath, result);  // i+1 = no reuse
        // or i = allow reuse of same element (Combination Sum)

        // 3. UNCHOOSE: remove from path (backtrack)
        currentPath.pop();
    }
}
// The 3 steps: Choose → Recurse → Unchoose
// The spread [...currentPath] is critical — without it, all results point to same array

// INORDER: left → root → right → gives sorted order for BST
function inorder(root, result = []) {
    if (!root) return result;
    inorder(root.left, result);
    result.push(root.val);
    inorder(root.right, result);
    return result;
}

// PREORDER: root → left → right → used to clone/serialize a tree
function preorder(root, result = []) {
    if (!root) return result;
    result.push(root.val);      // process root FIRST
    preorder(root.left, result);
    preorder(root.right, result);
    return result;
}

// POSTORDER: left → right → root → used to delete a tree, evaluate expressions
function postorder(root, result = []) {
    if (!root) return result;
    postorder(root.left, result);
    postorder(root.right, result);
    result.push(root.val);      // process root LAST
    return result;
}

Level Order BFS — the template
function levelOrder(root) {
    if (!root) return [];
    const result = [], queue = [root];

    while (queue.length) {
        const levelSize = queue.length;  // snapshot current level size
        const level = [];

        for (let i = 0; i < levelSize; i++) {
            const node = queue.shift();
            level.push(node.val);
            if (node.left) queue.push(node.left);
            if (node.right) queue.push(node.right);
        }
        result.push(level);
    }
    return result;
}
// Key: capture levelSize BEFORE the loop — queue grows during the loop
// This separates processing one level at a time

Exactly what to learn
  • BST property: for every node, ALL values in left subtree < node < ALL values in right subtree
  • Inorder of BST: gives sorted ascending order — this property solves many BST problems
  • Search: O(h) where h = height. Balanced BST: O(log n). Skewed: O(n)
  • Validate BST: pass min/max bounds down recursively. Left subtree: max = current val. Right subtree: min = current val.
