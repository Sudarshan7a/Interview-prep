Section 01

The Core Idea

Two pointers replaces the brute-force inner loop when the array is sorted or has a structural property that tells you which direction to move.

In the brute force for pair-finding problems, you have two nested loops — one pointer that moves forward, another that scans everything after it. Two pointers eliminates the inner scan by starting both ends simultaneously and using the problem's structure to decide which pointer to move.

The key pre-condition: Two Pointers on a sorted array (or reversed string/palindrome check) works because sortedness gives you directionality — if the sum is too large, move right inward. If too small, move left outward. This directionality collapses O(n²) to O(n). Without this structure, you need a HashMap instead (Part 0).

How to instantly spot it: The problem mentions a sorted array, or asks about palindromes, or asks to remove duplicates/elements from a sorted array in-place, or involves merging two arrays. These are all Two Pointer problems.

Use Two Pointers when:

✓ Array is sorted and you need to find a pair with some condition
✓ You need to check if a string is a palindrome
✓ Remove duplicates from sorted array in-place (no extra space)
✓ Merge two sorted arrays
✓ Move or partition elements: zeros to end, negatives to front
✓ 3Sum / 4Sum — fix one element, two-pointer the rest
✓ Container With Most Water — maximize based on boundary choice
Two Pointers vs HashMap — how to choose:

Array is sorted? → Two Pointers (no extra space, O(n))
Array is unsorted? → HashMap (O(n) but O(n) space)
Need to find pair with sum = target → both work, sorted → Two Pointers
Need to count pairs / group things → HashMap
Problem says O(1) space → Two Pointers (HashMap costs O(n) space)

The 4 Two Pointer Variants

Every two pointer problem is one of these four shapes. Recognize the variant → apply the right template.
Variant A
Opposite Ends → Meet in Middle
L starts at 0, R starts at end. Move based on condition. Stop when L ≥ R. Use for: pair sums, palindrome check, container water.
Two Sum II, Valid Palindrome, Container With Most Water, 3Sum
Variant B
Same Direction — Fast/Slow
Slow writes valid values, Fast reads ahead. Use for: removing duplicates/elements in-place from sorted array.
Remove Duplicates, Remove Element, Move Zeroes
Variant C
Two Arrays — One Pointer Each
One pointer per array, both move forward. Compare and advance the smaller/matching one. Use for: merging sorted arrays, comparing strings with deletions.
Merge Sorted Array, Backspace String Compare, Squares of Sorted Array
Variant D
Fix One + Two Pointer Rest
Outer loop fixes one element. Inner two-pointer finds the rest. The classic O(n²) answer to 3Sum — optimal because inner is O(n) not O(n²).

Section 03

Two Pointer Interview Framework

What to say, what to draw, and what pitfalls to mention before you code a single line.
1
Confirm sorted — it's the prerequisite
The first thing to ask: "Is the array sorted?" If yes, two pointers. If no, ask if you can sort it (O(n log n) overhead, but might still be better than O(n²)). If sorting is not allowed and order matters, pivot to HashMap. Never use two pointers on an unsorted array for pair-finding — it won't work.
"Is the array sorted? That affects my approach. If sorted, I can use two pointers in O(n). If not, I'd use a HashMap in O(n) time but O(n) space — or sort first in O(n log n)."
2
Identify the variant — say it explicitly
Name the variant before coding: "This is an opposite-ends problem" or "This is a fast/slow pointer — slow writes, fast reads." Naming the pattern shows the interviewer you have a mental model, not just a memorized solution.
"I'll use two pointers from opposite ends. Left starts at 0, Right starts at the end. I move them based on whether the sum is too large or too small."
3
State the move condition before coding
The move condition is the heart of the algorithm. Say it in plain English before writing it in code. Interviewers want to see your logic, not just your syntax. "If the current sum is too large, moving Right leftward decreases it. If too small, moving Left rightward increases it."
"If sum > target: right pointer moves left (decreases sum). If sum < target: left pointer moves right (increases sum). If equal: found the pair. This works because the array is sorted — moving a pointer always changes the sum predictably."
4
Handle duplicates explicitly for 3Sum
3Sum has a notorious duplicate-skipping step that many freshers forget. After finding a triplet, you must skip all duplicates on both ends to avoid repeating the same triplet. Mention this proactively — it shows experience. "After recording a valid triplet, I skip duplicates on both L and R before continuing."
"One tricky part is de-duplication. After finding a triplet [a,b,c], I need to skip over any duplicate values at L and R before the next iteration — otherwise I'll count the same triplet multiple times."
5
Trace a small example + state complexity
After coding: walk through one iteration manually. State O(n) time, O(1) space (the key advantage over HashMap). Mention edge cases: empty array, all same element, no valid pair exists.
"Time: O(n) — both pointers traverse the array once total. Space: O(1) — just two index variables, no extra data structures. This is the advantage over the HashMap approach which uses O(n) space."
The most common Two Pointer mistakes in interviews:

✗ Forgetting to check L < R (not L <= R) — when L equals R it's the same element
✗ In 3Sum: not skipping duplicates after finding a valid triplet → duplicate results
✗ In 3Sum: also not skipping duplicates for the outer fixed element
✗ Moving both pointers when you should move only one
✗ Using two pointers on unsorted array and wondering why it doesn't work
Section 04

The 4 Templates

Memorize these skeletons. Fill in the condition and action per problem.
JavaScriptTemplate A — Opposite Ends
function twoPointerOpposite(arr, target) {
    let L = 0, R = arr.length - 1;

    while (L < R) {              // strict < — when equal, same element
        const val = arr[L] + arr[R]; // or whatever condition

        if (val === target) {
            return [L, R];           // found — return what's needed
        } else if (val < target) {
            L++;                     // need larger sum → move L right
        } else {
            R--;                     // need smaller sum → move R left
        }
    }
    return [];                     // no valid pair found
}
JavaScriptTemplate B — Fast/Slow (in-place write)
function fastSlowWrite(arr) {
    let slow = 0;                  // slow: next valid write position

    for (let fast = 0; fast < arr.length; fast++) {
        if (/* arr[fast] is a valid element to keep */) {
            arr[slow] = arr[fast]; // write valid element at slow position
            slow++;
        }
        // else: skip — fast moves on, slow stays (overwrite next time)
    }

    return slow;                   // slow = new length of valid portion
}
// What changes: the "is valid" condition
// Remove duplicates: arr[fast] !== arr[slow - 1]
// Remove element k: arr[fast] !== k
// Move zeroes: arr[fast] !== 0
JavaScriptTemplate C — Two Arrays
function twoArrays(arr1, arr2) {
    let p1 = 0, p2 = 0;
    const result = [];

    while (p1 < arr1.length && p2 < arr2.length) {
        if (arr1[p1] <= arr2[p2]) {
            result.push(arr1[p1++]); // take from arr1, advance p1
        } else {
            result.push(arr2[p2++]); // take from arr2, advance p2
        }
    }

    // Drain remaining (only one will have elements left)
    while (p1 < arr1.length) result.push(arr1[p1++]);
    while (p2 < arr2.length) result.push(arr2[p2++]);

    return result;
}
JavaScriptTemplate D — Fix one + Two Pointer (3Sum)
function fixPlusTwoPointer(arr, target) {
    arr.sort((a, b) => a - b);    // MUST sort first
    const result = [];

    for (let i = 0; i < arr.length - 2; i++) {
        // Skip duplicate values for the fixed element
        if (i > 0 && arr[i] === arr[i - 1]) continue;

        let L = i + 1, R = arr.length - 1;

        while (L < R) {
            const sum = arr[i] + arr[L] + arr[R];

            if (sum === target) {
                result.push([arr[i], arr[L], arr[R]]);
                // Skip duplicates on both ends
                while (L < R && arr[L] === arr[L + 1]) L++;
                while (L < R && arr[R] === arr[R - 1]) R--;
                L++; R--;
            } else if (sum < target) {
                L++;
            } else {
                R--;
            }
        }
    }
    return result;
}

Problem 01 of 05Easy
Valid Palindrome
LeetCode #125 · leetcode.com/problems/valid-palindrome
1
Problem: A phrase is a palindrome if, after converting to lowercase and removing non-alphanumeric characters, it reads the same forward and backward. Return true/false.
2
Brute force: Clean the string (filter and lowercase), reverse it, compare. O(n) time, O(n) space for the cleaned/reversed copies. Valid but uses extra space.
3
Two pointer approach: L from left, R from right. Skip non-alphanumeric characters on each side. Compare characters at L and R (case-insensitive). If mismatch → not a palindrome. If L ≥ R → it's a palindrome. O(1) space.
4
Alphanumeric check: Use regex /[a-z0-9]/ after lowercasing — or check char code ranges: a-z (97-122), A-Z (65-90), 0-9 (48-57). In an interview, the regex version is cleaner and acceptable.
Interviewer
Is this string a valid palindrome? Only alphanumeric characters count.
You
So spaces and punctuation are ignored? And comparison is case-insensitive?
Interviewer
Correct. "A man, a plan, a canal: Panama" should return true.
You
I can do this two ways. Brute force: clean the string, reverse, compare — O(n) space. Better: two pointers from opposite ends, skip non-alphanumeric chars as I go — O(1) space. I'll go with two pointers.
You
L starts at 0, R at the end. Skip any character at L or R that isn't alphanumeric. Then lowercase and compare. If they differ, return false. If L reaches R without a mismatch — it's a palindrome.
Interviewer
What's your alphanumeric check?
You
I'll lowercase the character and test against /[a-z0-9]/. Alternatively, check char code ranges — 'a'-'z' is 97-122, '0'-'9' is 48-57. Either works — regex is cleaner to read.
JavaScriptValid Palindrome — O(1) space
function isPalindrome(s) {
    let L = 0, R = s.length - 1;

    const isAlnum = (ch) => /[a-z0-9]/.test(ch.toLowerCase());

    while (L < R) {
        // Skip non-alphanumeric on left
        while (L < R && !isAlnum(s[L])) L++;
        // Skip non-alphanumeric on right
        while (L < R && !isAlnum(s[R])) R--;

        // Compare (case-insensitive)
        if (s[L].toLowerCase() !== s[R].toLowerCase()) {
            return false;
        }
        L++; R--;
    }

    return true;
}
Time: O(n) — both pointers traverse at most n chars total Space: O(1) — no extra arrays
  • Empty string "": L=0, R=-1. While condition L < R is false immediately. Return true. Empty string is technically a palindrome.
  • All non-alphanumeric "!@#": Both pointers skip everything, L and R meet. Return true.
  • Single char "a": L=0, R=0. L < R is false. Return true — single char is palindrome.
  • Case: "racecar" vs "Race car": Both are palindromes after cleaning. Lowercase comparison handles it.
  • The brute force one-liner: const clean = s.toLowerCase().replace(/[^a-z0-9]/g, ''); return clean === clean.split('').reverse().join(''). Fine for interviews if they don't care about space. Mention the O(n) space cost.
Problem 02 of 05Medium
Two Sum II — Input Array Is Sorted
LeetCode #167 · leetcode.com/problems/two-sum-ii
1
Problem: Given a sorted 1-indexed array, return the 1-indexed positions of two numbers that add to target. Must use O(1) space (per problem constraint).
2
Why not HashMap: The problem explicitly requires O(1) space. This rules out the HashMap approach from Part 0. The sorted constraint makes two pointers perfect.
3
Move logic: If nums[L] + nums[R] < target → the sum is too small. To increase it, move L right (larger values to the right, since array is sorted). If sum > target → move R left. If equal → found.
4
Why this works: At each step, we eliminate an entire row or column of the O(n²) search space. Moving L right eliminates all pairs involving the old L value (they'd all be too small). Moving R left eliminates all pairs involving the old R value. Total eliminations = O(n). No pair is ever checked twice.
Interviewer
Same as Two Sum, but the array is sorted and you must use O(1) space.
You
Since the array is sorted and space is O(1), this is the classic two pointer problem. HashMap won't work here because it needs O(n) space.
You
L at index 0, R at the last index. If their sum equals target — done. If sum is too small — I need a larger left value, so L moves right. If sum is too large — I need a smaller right value, so R moves left. The sorted order guarantees every move either increases or decreases the sum predictably.
Interviewer
Why is this guaranteed to find the answer?
You
The problem guarantees exactly one answer exists. At each step, we eliminate at least one element from consideration — either the current L (too small to form any valid pair) or the current R (too large). We never skip the valid pair because: if we move L, it's because L was too small with the current R, and it's also too small with any smaller R value. So we don't need to check those pairs. Same logic for moving R.
JavaScriptTwo Sum II — O(n) time, O(1) space
function twoSum(numbers, target) {
    let L = 0, R = numbers.length - 1;

    while (L < R) {
        const sum = numbers[L] + numbers[R];

        if (sum === target) {
            return [L + 1, R + 1]; // 1-indexed answer
        } else if (sum < target) {
            L++;  // sum too small → need larger left value
        } else {
            R--;  // sum too large → need smaller right value
        }
    }

    return []; // guaranteed to find, but handle gracefully
}
Time: O(n) — L and R together traverse n positions Space: O(1) — two index variables only
  • Array of 2: L=0, R=1. Check once. Return [1,2]. Correct.
  • Answer at ends: nums=[1,10], target=11. L=0, R=1. sum=11. Return [1,2].
  • 1-indexed return: The problem is 1-indexed. Return [L+1, R+1]. Easy to forget — mention it explicitly.
  • Negative numbers: Works fine — move logic is the same. Sum too small → L++. Too large → R--.
  • vs Part 0 Two Sum: Part 0 array is unsorted → HashMap. This one is sorted → Two Pointers. Both are O(n). This one is O(1) space — the advantage.
Problem 03 of 05Easy
Remove Duplicates from Sorted Array
LeetCode #26 · leetcode.com/problems/remove-duplicates-from-sorted-array
1
Problem: Remove duplicates from a sorted array in-place. Return the count of unique elements. The first k elements of the array should be the unique values.
2
Key insight: The array is sorted — all duplicates are adjacent. Use fast/slow pointers: slow tracks the next position to write a unique value. fast reads ahead to find the next unique value.
3
When to write: If nums[fast] !== nums[slow - 1] (the last written unique value), then nums[fast] is a new unique element — write it at nums[slow] and increment slow.
4
Mental model: Slow is the "write head" — it only advances when a new unique value is found. Fast is the "read head" — it always advances. At the end, slow = count of unique elements.
Interviewer
Remove duplicates in-place from a sorted array. Return the count of unique elements.
You
Since it's sorted, duplicates are adjacent. I'll use a fast/slow pointer. Slow is my write position — it only moves when I find a new unique element. Fast reads ahead looking for unique values. When fast finds something different from the last thing slow wrote, I copy it to the slow position and advance slow.
Interviewer
What does slow start at?
You
I initialize slow to 1 — the first element is always unique, so slow starts at position 1 (ready to write the second unique element). Fast starts at 1 as well, reading from position 1. When fast finds nums[fast] !== nums[slow-1], I write it at nums[slow] and slow++.
Interviewer
What's the return value?
You
The slow pointer value at the end — it represents how many unique elements I wrote. The first slow elements of the array now contain those unique values in order.
JavaScriptRemove Duplicates — O(n) time, O(1) space
function removeDuplicates(nums) {
    if (nums.length === 0) return 0;

    let slow = 1; // first element is always unique; start writing at index 1

    for (let fast = 1; fast < nums.length; fast++) {
        // If this element differs from the last written unique value
        if (nums[fast] !== nums[slow - 1]) {
            nums[slow] = nums[fast]; // write it
            slow++;                  // advance write head
        }
        // else: skip duplicate — fast will advance on next iteration
    }

    return slow; // count of unique elements
}

// Example: [1,1,2,3,3]
// After: [1,2,3,_,_], returns 3
Time: O(n) — single pass Space: O(1) — in-place modification
  • Empty array: Guard at top returns 0.
  • All duplicates [1,1,1]: slow stays at 1. fast advances through all. Return 1. Correct.
  • No duplicates [1,2,3]: Every element is unique. slow = 3 = array length. Correct.
  • Single element: [5] → slow=1, fast starts at 1, loop doesn't run. Return 1. Correct.
  • Why slow starts at 1: Index 0 is always kept (first element). Slow points to next write position. Starting at 1 means "I've already counted index 0 as unique."
Problem 04 of 05Medium
3Sum
LeetCode #15 · leetcode.com/problems/3sum
1
Problem: Find all unique triplets [a, b, c] where a + b + c = 0. No duplicate triplets.
2
Reduction: Fix one element (outer loop on i). The remaining problem is Two Sum II: find two numbers in the subarray [i+1..n-1] that sum to -nums[i]. Sort first to enable two pointers.
3
Outer loop de-dup: If nums[i] === nums[i-1], skip — we already processed this value. Prevents duplicate triplets at the "a" position.
4
Inner two-pointer de-dup: After recording a valid triplet, skip all consecutive duplicates at L and R before moving inward. Prevents duplicate triplets at "b" and "c" positions.
5
Optimization: If nums[i] > 0, break — since the array is sorted, all remaining triplets would have positive sum, never reaching 0.
Interviewer
Find all unique triplets that sum to zero.
You
The brute force is three nested loops — O(n³). Can I sort the array?
Interviewer
Yes.
You
I'll sort, then reduce 3Sum to 2Sum. Outer loop fixes element nums[i]. For each fixed element, I run two pointers on the remaining subarray to find pairs summing to -nums[i]. That's O(n) per outer iteration, O(n²) total. Optimal.
You
The tricky part is de-duplication. For the outer element: if nums[i] equals nums[i-1], skip it. For the inner pairs: after finding a valid triplet, skip all duplicates at both L and R before moving inward.
Interviewer
Why do you need to de-duplicate at both the outer and inner level?
You
Without outer de-dup: if nums=[0,0,0,0] and i=0 finds [0,0,0], i=1 would find the same triplet again. Without inner de-dup: after finding [a,b,c], if there are multiple b's or c's, we'd push [a,b,c] multiple times. Both checks prevent duplicate triplets in the output.
JavaScript3Sum — O(n²) time, O(1) extra space
function threeSum(nums) {
    nums.sort((a, b) => a - b); // sort ascending first — required
    const result = [];

    for (let i = 0; i < nums.length - 2; i++) {
        // Optimization: if smallest remaining is positive, no solution
        if (nums[i] > 0) break;

        // Skip duplicate values for the fixed element
        if (i > 0 && nums[i] === nums[i - 1]) continue;

        let L = i + 1, R = nums.length - 1;

        while (L < R) {
            const sum = nums[i] + nums[L] + nums[R];

            if (sum === 0) {
                result.push([nums[i], nums[L], nums[R]]);

                // Skip duplicates at L and R before moving inward
                while (L < R && nums[L] === nums[L + 1]) L++;
                while (L < R && nums[R] === nums[R - 1]) R--;
                L++; R--;

            } else if (sum < 0) {
                L++;
            } else {
                R--;
            }
        }
    }

    return result;
}
Time: O(n²) — O(n log n) sort + O(n) per outer iteration × O(n) outer Space: O(1) extra — output not counted
  • [0,0,0]: i=0, L=1, R=2. sum=0. Push [0,0,0]. Skip duplicates: L tries to advance but L=R already. Return [[0,0,0]].
  • All positives [1,2,3]: i=0: nums[0]=1 > 0 → break. Return []. Correct.
  • All same negatives [-2,-2,-2]: i=0: target=-(-2)=2. L=1 (-2), R=2 (-2). sum=-6 < 0 → L++. L=R=2, exit. i=1: skip (same as i=0). Return [].
  • Outer de-dup condition: i > 0: The condition must be i > 0 to avoid out-of-bounds on i-1. Never skip i=0 even if nums[0] appears multiple times — we need to process it at least once.
  • Inner de-dup: after push, before L++ R--: Skip THEN increment. If you increment first, you might re-enter the same position.
Problem 05 of 05Medium
Container With Most Water
LeetCode #11 · leetcode.com/problems/container-with-most-water
1
Problem: Given heights array, find two lines that form a container holding the most water. Water = min(height[L], height[R]) × (R - L).
2
Brute force: Check every pair. O(n²). Too slow.
3
Key insight — why move the shorter pointer: The water is bounded by the shorter line. If we move the taller pointer inward, we decrease the width AND the height is still bounded by the shorter line — water can only decrease or stay same. Moving the shorter pointer inward at least has a chance of finding a taller line, possibly increasing water. So always move the shorter pointer.
4
Algorithm: L=0, R=end. At each step: calculate water with current L and R. Update max. Move the shorter of L or R inward. Stop when L meets R.
5
Proof it doesn't miss the answer: We only move the shorter pointer. All pairs involving the shorter pointer with a wider width have already been evaluated (they'd be even smaller since width was larger but height still bounded by the same short line). So we can safely eliminate them.
Interviewer
Find the container that holds the most water.
You
Water is bounded by the shorter line and limited by the width. Brute force: every pair — O(n²). I'll use two pointers — O(n).
You
L at 0, R at end. At each step, compute water: min(height[L], height[R]) times (R minus L). Track the maximum. Then move the shorter pointer inward.
Interviewer
Why move the shorter pointer and not the taller one?
You
If we move the taller pointer inward: the width decreases, and the height is still bounded by the shorter line. Water can only stay the same or decrease — we gain nothing. Moving the shorter pointer is the only way we might find a taller line and potentially increase water. So moving the shorter pointer is always at least as good as moving the taller one.
Interviewer
Can you prove it doesn't miss the optimal pair?
You
When we move the shorter pointer at L, we're saying: "L paired with any R' where R' is between L and R will have less water — smaller width, height still bounded by the shorter (old L). So we haven't missed any better pair involving old L." By induction, every optimal pair is considered.
JavaScriptContainer With Most Water — O(n)
function maxArea(height) {
    let L = 0, R = height.length - 1;
    let maxWater = 0;

    while (L < R) {
        // Water = shorter height × width
        const water = Math.min(height[L], height[R]) * (R - L);
        maxWater = Math.max(maxWater, water);

        // Move the shorter pointer — only way to potentially improve
        if (height[L] < height[R]) {
            L++;
        } else {
            R--;  // if equal, doesn't matter which — move either
        }
    }

    return maxWater;
}
Time: O(n) — L and R together traverse n positions Space: O(1)
  • Two elements: [1,2] → water = min(1,2)*1 = 1. L and R meet. Return 1.
  • All equal heights [5,5,5,5]: Maximum container is outermost: 5×3=15. Pointers move inward, but water always decreases with width. maxWater stays 15.
  • Equal heights at L and R: When height[L] === height[R], moving either pointer is fine. The current water is already computed — moving either R-- or L++ is correct. Convention: move R-- (or either).
  • Why NOT the Elevation Map / Trapping Rainwater pattern: This problem is about ONE container (two boundaries). Trapping Rainwater (#42) is a different problem where water fills ALL valleys — different algorithm (prefix max arrays or monotonic stack).

15 Interview Questions

Try answering out loud before expanding. These are real questions from Bangalore product company interviews.
CoreWhen do you use Two Pointers instead of a HashMap?▼
Use Two Pointers when: (1) The array is sorted — sortedness gives directionality, telling you which pointer to move. (2) You need O(1) space — HashMap costs O(n) space, Two Pointers uses just two index variables. (3) The problem involves in-place modification of a sorted array (remove duplicates, remove element). Use HashMap when: (1) Array is unsorted and sorting would change the meaning. (2) You need to associate a value with what you've seen (store index, count, etc.). (3) Space is not constrained. Rule: If sorted → Two Pointers first. If unsorted and you can't sort → HashMap.
VSWhat is the difference between Two Pointers and Sliding Window?▼
Both use two index variables. Difference: Two Pointers — pointers move independently based on comparisons. Can move toward each other (opposite ends) or in the same direction at different rates (fast/slow). The window between them doesn't have a fixed constraint. Sliding Window — the window maintains a specific condition (fixed size, or a constraint on what's inside). When the constraint is violated, one end moves to restore it. The window usually only expands/shrinks from one end at a time. Example: Two Pointers for pair sum in sorted array (pointers converge based on sum). Sliding Window for longest substring without repeating characters (window expands with fast, shrinks with slow when duplicate appears). The key question: "Does the window maintain a specific invariant?" If yes, Sliding Window. If the two indices just move based on comparison, Two Pointers.
InterviewWalk me through 3Sum. Why O(n²) and not O(n³)?▼
3Sum: sort the array O(n log n). Outer loop iterates i from 0 to n-3 — O(n) iterations. For each i, run two pointers on the remaining subarray [i+1..n-1] — that's O(n) in total across both pointers (they move inward and never backtrack). So total: O(n) outer × O(n) inner two pointers = O(n²). Brute force is O(n³) because: three nested loops, each iterating independently, O(n) each. Two Pointers eliminates the third loop by using sortedness — instead of scanning all pairs [L, R] for each i, we start from opposite ends and move based on whether the sum is too large or too small, hitting each pair at most once — O(n) for the inner pass.
TrapWhat is the de-duplication logic in 3Sum? Why is it easy to get wrong?▼
Two levels of de-duplication: Outer (fixed element): if (i > 0 && nums[i] === nums[i-1]) continue. If the current fixed element equals the previous one, skip — we'd find the same triplets again. The i > 0 guard prevents index -1 access. Inner (L and R after finding a triplet): After pushing a valid triplet, skip consecutive duplicates at L (while L < R && nums[L] === nums[L+1], L++) and at R (while L < R && nums[R] === nums[R-1], R--). Then do L++; R--. Why it's wrong to forget: [-2,0,0,2,2] with target 0. Without inner de-dup, after finding [−2,0,2], you'd push [−2,0,2] again for the second 0 and second 2. Common mistake: doing L++ R-- before the duplicate-skip loop, or skipping when L === R (but the guard L < R prevents this). Another mistake: skipping at i=0 — the condition must be i > 0, never skip the very first element.
InterviewWhy do we move the shorter pointer in Container With Most Water?▼
Water = min(height[L], height[R]) × (R - L). The water is bounded by the shorter of the two walls. If we move the taller pointer inward: width decreases, and height is still bounded by the shorter wall (which didn't move) — water can only decrease or stay same. We gain nothing. If we move the shorter pointer inward: width decreases, but there's a chance we find a taller wall — the min might increase, potentially increasing water. The greedy insight: moving the shorter pointer is the only action that can possibly improve the result. Moving the taller pointer is strictly non-improving. So we always move the shorter one. This greedy choice can be proven by contradiction: if the optimal pair has a shorter left wall, and we're currently at a taller left wall — moving right (shortening L would only happen if L was shorter) would eventually reach the optimal pair. The algorithm never eliminates the optimal pair because we only move the pointer that cannot be part of a better solution at its current position.
CoreWhat is the fast/slow pointer pattern? Name 3 problems that use it.▼
Fast/Slow pointers: slow moves only when a condition is met (writes valid elements), fast always moves forward (reads ahead). The "slow" pointer marks the boundary of valid processed elements; "fast" explores ahead. Three problems: (1) Remove Duplicates (#26): slow writes unique elements. Fast reads ahead. If fast finds a new unique value (differs from last written), write at slow and advance slow. (2) Remove Element (#27): slow writes elements ≠ target. Fast reads all. If fast finds valid element, write at slow. (3) Move Zeroes (#283): slow is next position for non-zero. Fast reads. If fast finds non-zero, swap arr[slow] and arr[fast], advance slow. Also applies to Linked Lists: Floyd's Cycle Detection — slow moves 1 step, fast moves 2. If they meet, there's a cycle.
TrapWhy must L < R (not L <= R) in the while loop?▼
When L === R, both pointers point to the same element. Using that element twice would violate the "each element used once" constraint (same as using index twice in Two Sum). For pair problems: you need two distinct elements — L and R must be different indices. With L <= R: when L === R, you'd check nums[L] + nums[R] = nums[i] + nums[i] = 2*nums[i] — you'd use the same element twice, which is wrong. With L < R: the loop exits when they meet, before checking the same element against itself. Exception: if the problem explicitly allows using the same element twice (which it would state), you'd use L <= R. For palindrome: L < R also — when L === R it's the middle character of an odd-length string, which automatically equals itself, so no check needed.
InterviewHow do you solve Trapping Rain Water with Two Pointers?▼
Trapping Rain Water (#42): water at each position = min(maxLeft, maxRight) - height[i]. Brute force: compute max left and max right for every position — O(n²). Better: precompute prefix max arrays — O(n) time, O(n) space. Two Pointer (O(1) space): L=0, R=n-1, maxLeft=0, maxRight=0. At each step: if height[L] <= height[R] → the right side is tall enough, water at L = maxLeft - height[L] (bounded by left). Add to result, update maxLeft, L++. Else → the left side is tall enough, water at R = maxRight - height[R]. Add to result, update maxRight, R--. Key insight: when height[L] <= height[R], we know maxRight >= height[R] >= height[L], so water at L is definitely bounded by maxLeft. We can process L confidently without knowing the exact maxRight. Symmetric for R.
CoreHow do you merge two sorted arrays with two pointers?▼
Classic merge from merge sort. Two pointers p1=0 (arr1), p2=0 (arr2). Compare arr1[p1] and arr2[p2]. Take the smaller one into result, advance that pointer. Repeat until one array is exhausted. Drain the remaining array. O(n + m) time, O(n + m) space for result. For LeetCode #88 (Merge Sorted Array): merge into arr1 which has space. Trick: merge from the BACK to avoid overwriting elements we haven't processed yet. p1 = m-1 (last real element of arr1), p2 = n-1 (last of arr2), write = m+n-1 (last position of arr1). Take the larger of p1 and p2, write it at 'write', decrement. This way we never overwrite an unread element. O(m+n) time, O(1) extra space.
TrapHow do you handle the case where you don't know which direction to move?▼
This happens when the move condition isn't obvious. Work through a small example with specific numbers and trace what happens with each choice: "If I move L now, what happens to the sum/value?" "If I move R, what happens?" The sorted order gives you the answer: moving L right always increases the minimum value accessible from left, moving R left always decreases the maximum value accessible from right. If your condition is sum-based: too small → you need larger, so move the side that increases sum (move L right in ascending array). Too large → move the side that decreases sum (move R left). If it's not obvious from the problem's structure, consider whether Two Pointers is the right approach — maybe the array needs sorting first, or maybe a different pattern applies entirely.
InterviewHow does Dutch National Flag (Sort Colors) work?▼
Sort Colors (#75): array with 0s, 1s, 2s. Sort in one pass, O(1) space. Three pointers: low=0 (next 0 position), mid=0 (current), high=n-1 (next 2 position). While mid <= high: if nums[mid] === 0: swap nums[low] and nums[mid], low++, mid++. If nums[mid] === 1: mid++ (already in place). If nums[mid] === 2: swap nums[mid] and nums[high], high-- (DON'T increment mid — we just received an unknown value at mid). The asymmetry: when we swap with low, we know we got a 1 or 0 back (low has already been processed), so mid can advance. When we swap with high, we don't know what we got at mid — must process it again. This gives one-pass O(n) sort for 3-valued arrays.
VSTwo Pointers vs Binary Search — when to use each on sorted arrays?▼
Binary Search: when you're looking for a specific target in O(log n). The answer is a single position or value. Works by halving the search space each step. Use for: "Is X in this array?", "What is the smallest value satisfying condition Y?", "Find the insertion point." Two Pointers: when the answer involves a relationship between two elements (pair, triplet). Both pointers traverse the array. Use for: pair sum, palindrome, partition problems. Rule: if the problem is "find one thing" in a sorted array → Binary Search. If it's "find two things that relate to each other" → Two Pointers. Sometimes they combine: 3Sum uses outer loop (linear scan) + inner Two Pointers. Finding k closest elements (#658) uses binary search to find the starting position, then possibly two pointers to expand.
InterviewHow do you check if a string is a palindrome ignoring non-alphanumeric characters?▼
Two approaches: (1) Clean and compare: const clean = s.toLowerCase().replace(/[^a-z0-9]/g,''); return clean === clean.split('').reverse().join('') — O(n) time, O(n) space for the cleaned copy and reversed copy. (2) Two pointers (O(1) space): L=0, R=end. Inner loops skip non-alphanumeric on each side. Compare lowercased characters. Return false on mismatch, return true if L reaches R. Alphanumeric check: /[a-z0-9]/.test(ch.toLowerCase()) or check char code: 'a'-'z' (97-122), 'A'-'Z' (65-90), '0'-'9' (48-57). In an interview: say both approaches, mention space trade-off, code the two-pointer version if space matters. Two pointers is preferred — it shows you know the pattern and it's more efficient in space.
CoreWhat is the time complexity of Two Pointers? Why is it O(n) not O(n²)?▼
Two pointers runs in O(n) because each pointer moves in only one direction, and together they traverse at most n steps total. For opposite-ends: L can only move right (0 to n-1), R can only move left (n-1 to 0). Each pointer moves at most n times. Total moves ≤ 2n = O(n). A pair (L, R) is only "checked" when both pointers are there simultaneously. Each check advances at least one pointer, so there are at most n checks total. For brute force: L tries all n positions, R tries all n positions independently — O(n²) pairs. Two pointers works because it uses sortedness to eliminate entire categories of pairs without checking them: "If nums[L] + nums[R] < target, then nums[L] + nums[R-1] < target too — skip all those. Move L to a larger value." Each pointer move eliminates O(1) future comparisons — total O(n) instead of O(n²).
InterviewDescribe a situation where Two Pointers does NOT work. What would you use instead?▼
Two Pointers fails when: (1) Array is unsorted and sorting changes the meaning: Original Two Sum (unsorted, return indices) — sorting would scramble indices. Use HashMap. (2) You need O(n²) precision about all pairs: Count pairs where nums[i] + nums[j] = k for ALL pairs, including counting duplicates separately — Two Pointers might miss pair counts. Use HashMap with frequency. (3) The condition is not monotonic: "Find pair with maximum product" in an unsorted array — Two Pointers can't determine which direction to move. Sort first or use different approach. (4) Problem involves non-contiguous elements with complex conditions: "Find three elements where each is in a different third of the array" — fixed structure, doesn't benefit from two-pointer traversal. In general: if moving a pointer doesn't reliably tell you whether you're getting closer to the answer, Two Pointers won't work correctly.
