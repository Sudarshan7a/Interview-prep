Graphs

Graphs = nodes + edges. Most real-world systems (social networks, maps, dependencies) are graphs. The core algorithms: BFS (shortest path, level by level), DFS (explore fully, detect cycles), topological sort (ordering with dependencies), Dijkstra (weighted shortest path).

Graph representation + BFS/DFS first
✓
Graph representation + BFS template
Adjacency list, adjacency matrix, BFS for shortest path in unweighted graph
must · foundation
Exactly what to learn
  • Adjacency list: Map/array where graph[node] = [list of neighbors]. Space: O(V+E). Use for sparse graphs.
  • Adjacency matrix: 2D array graph[i][j] = 1 if edge. Space: O(V²). Use for dense graphs or when edge lookup needed in O(1).
  • BFS pattern: queue + visited set. Process level by level. Gives shortest path in unweighted graphs.
  • Why BFS = shortest path: first time you reach a node is via the fewest hops (queue processes by distance)
  • Grid problems: treat each cell as a node, neighbors = up/down/left/right — same BFS/DFS patterns apply
BFS template — use for all graph BFS problems
BFS — shortest path template
function bfs(graph, start) {
    const visited = new Set([start]);
    const queue = [start];
    let distance = 0;

    while (queue.length) {
        const levelSize = queue.length;  // process one level at a time
        for (let i = 0; i < levelSize; i++) {
            const node = queue.shift();
            if (node === target) return distance;  // found!
            for (const neighbor of graph[node]) {
                if (!visited.has(neighbor)) {
                    visited.add(neighbor);  // mark BEFORE adding to queue
                    queue.push(neighbor);
                }
            }
        }
        distance++;
    }
    return -1;  // unreachable
}
// Critical: mark visited when ADDING to queue, not when processing
// Otherwise same node gets added multiple times → wrong result

DFS on graphs + Cycle detection
DFS template, detect cycle in directed/undirected graph, connected components
must
Exactly what to learn
  • DFS: go as deep as possible before backtracking. Uses recursion (call stack) or explicit stack.
  • Cycle in undirected graph: during DFS, if you visit a neighbor that's already visited AND it's not your parent → cycle.
  • Cycle in directed graph: track three states — unvisited (0), in current path (1), done (2). Cycle if you visit a node with state 1 (currently in path).
  • Connected components: count of DFS/BFS starts needed to visit all unvisited nodes = number of components
  • Union-Find (Disjoint Set Union): alternative to DFS for connected components. O(α(n)) per operation.
Cycle detection in directed graph (3 states)
Directed graph cycle detection
function hasCycle(graph, node, state) {
    state[node] = 1;  // in current DFS path

    for (const neighbor of graph[node]) {
        if (state[neighbor] === 1) return true;   // back edge = cycle
        if (state[neighbor] === 0) {
            if (hasCycle(graph, neighbor, state)) return true;
        }
    }

    state[node] = 2;  // fully processed, safe
    return false;
}
// State: 0=unvisited, 1=in current path, 2=fully done
// This is same as Course Schedule solution

Topological Sort (BFS + DFS variants)
Kahn's algorithm (BFS in-degree), DFS-based, when to use
must
Exactly what to learn
  • Topological sort: linear ordering of nodes where all edges go from earlier to later. Only possible on DAGs (Directed Acyclic Graphs).
  • Kahn's algorithm (BFS): compute in-degree of all nodes. Start with nodes with in-degree 0. Process: add to result, decrement neighbors' in-degree, add neighbors with in-degree 0 to queue.
  • If result size < number of nodes → cycle exists (not all nodes could be processed)
  • Use case: course prerequisites, build systems, task scheduling
Kahn's Algorithm template
Topological Sort — Kahn's BFS algorithm
function topoSort(n, prerequisites) {
    const graph = Array.from({length: n}, () => []);
    const inDegree = new Array(n).fill(0);

    for (const [a, b] of prerequisites) {
        graph[b].push(a);   // b → a (b must come before a)
        inDegree[a]++;
    }

    const queue = [];
    for (let i = 0; i < n; i++) if (inDegree[i] === 0) queue.push(i);

    const order = [];
    while (queue.length) {
        const node = queue.shift();
        order.push(node);
        for (const next of graph[node]) {
            inDegree[next]--;
            if (inDegree[next] === 0) queue.push(next);
        }
    }
    return order.length === n ? order : [];  // [] = cycle detected
}

Dijkstra's Algorithm + Union-Find
Weighted shortest path, minimum spanning tree, connected components efficiently
must
Exactly what to learn
  • Dijkstra: shortest path in weighted graph with non-negative weights. Uses min-heap (priority queue). O((V+E) log V)
  • Process: start from source (dist=0). Always process node with minimum current distance. Update neighbors if shorter path found.
  • Why not BFS for weighted? BFS assumes all edges have weight 1. Dijkstra handles variable weights.
  • Union-Find (DSU): track which nodes belong to same component. Operations: find(x) returns root, union(x,y) merges components. With path compression + rank: nearly O(1) per operation.
  • Use Union-Find for: connected components, detecting cycles in undirected graphs, Kruskal's MST
Dijkstra template
Dijkstra — min-heap shortest path
function dijkstra(n, edges, src) {
    const graph = Array.from({length: n}, () => []);
    for (const [u, v, w] of edges) graph[u].push([v, w]);

    const dist = new Array(n).fill(Infinity);
    dist[src] = 0;

    // JS has no built-in heap — use array sorted as min-heap or a library
    // In interviews: use a simple priority queue simulation
    const pq = [[0, src]];  // [distance, node]

    while (pq.length) {
        pq.sort((a,b) => a[0] - b[0]);  // simulate min-heap (ok for interviews)
        const [d, node] = pq.shift();
        if (d > dist[node]) continue;  // stale entry, skip

        for (const [next, weight] of graph[node]) {
            const newDist = dist[node] + weight;
            if (newDist < dist[next]) {
                dist[next] = newDist;
                pq.push([newDist, next]);
            }
        }
    }
    return dist;
}

Dynamic Programming

DP = recursion + memoization, or bottom-up tabulation. The insight: overlapping subproblems — same sub-calculation needed many times. Cache it. The approach: always start with brute-force recursion, then add memoization, then convert to bottom-up table.

The DP learning approach — follow this order every time
3-step approach for every DP problem
Step 1: Write the brute-force recursive solution first. Step 2: Add a memo object — cache the result for each unique input. Step 3 (optional): Convert to bottom-up DP table (tabulation). Never skip Step 1. If you can't write the recursion, you can't write the DP.
✓
1D DP — linear state problems
Climbing stairs, house robber, coin change, word break — the 5 core patterns
must · start here
The DP mindset — what to ask for every problem
  • What is the state? (What changes between subproblems?)
  • What is the recurrence relation? (How does dp[i] relate to dp[i-1], dp[i-2]?)
  • What is the base case? (Smallest input with known answer)
  • What is the final answer? (dp[n]? max(dp)? dp[n][m]?)
House Robber — the canonical 1D DP example
House Robber — brute force → memo → tabulation
// STEP 1: Brute force recursion
function rob(nums, i = 0) {
    if (i >= nums.length) return 0;
    // At each house: rob it (skip next) OR skip it (consider next)
    return Math.max(
        nums[i] + rob(nums, i + 2),  // rob house i, skip i+1
        rob(nums, i + 1)                 // skip house i
    );
}  // O(2^n) — exponential, too slow

// STEP 2: Add memoization
function rob(nums) {
    const memo = {};
    function dfs(i) {
        if (i >= nums.length) return 0;
        if (memo[i] !== undefined) return memo[i];
        memo[i] = Math.max(nums[i] + dfs(i+2), dfs(i+1));
        return memo[i];
    }
    return dfs(0);
}  // O(n) time, O(n) space

// STEP 3: Bottom-up tabulation (no recursion)
function rob(nums) {
    let prev2 = 0, prev1 = 0;
    for (const n of nums) {
        const curr = Math.max(prev2 + n, prev1);
        prev2 = prev1;
        prev1 = curr;
    }
    return prev1;
}  // O(n) time, O(1) space — best solution

2D DP — two-variable state problems
LCS, edit distance, 0/1 knapsack, unique paths — when the state needs two dimensions
must
When do you need 2D DP?
  • When the state requires TWO independent variables (e.g., position in two strings, row+col in grid, item index + remaining capacity)
  • LCS (Longest Common Subsequence): dp[i][j] = length of LCS of s1[0..i] and s2[0..j]
  • Edit Distance: dp[i][j] = min operations to convert s1[0..i] to s2[0..j]
  • 0/1 Knapsack: dp[i][w] = max value using first i items with capacity w
  • Building 2D table: think about which cells you need to fill in what order
LCS — the canonical 2D DP
Longest Common Subsequence
function longestCommonSubsequence(text1, text2) {
    const m = text1.length, n = text2.length;
    // dp[i][j] = LCS of text1[0..i-1] and text2[0..j-1]
    const dp = Array.from({length: m+1}, () => new Array(n+1).fill(0));

    for (let i = 1; i <= m; i++) {
        for (let j = 1; j <= n; j++) {
            if (text1[i-1] === text2[j-1]) {
                dp[i][j] = 1 + dp[i-1][j-1];   // chars match: extend by 1
            } else {
                dp[i][j] = Math.max(dp[i-1][j], dp[i][j-1]);  // take best
            }
        }
    }
    return dp[m][n];
}

Heaps + Priority Queue

A heap gives you the min (or max) element in O(1), with insert and delete in O(log n). Signal: "find Kth largest/smallest", "merge K sorted lists", "stream median" → think heap.

Heap patterns — all use the same data structure
✓
Heap fundamentals + Top-K pattern
Min-heap vs max-heap, when to use each, the K-element heap trick
must
Exactly what to learn
  • Min-heap: smallest element always at top (root). Parent ≤ children.
  • Max-heap: largest element at top. Parent ≥ children.
  • JS has no built-in heap — in interviews either implement one or simulate with sorted array. Implement a simple MinHeap class (push, pop, peek) — takes 5 min to write from memory.
  • Top-K largest elements: maintain a min-heap of size K. When heap grows beyond K, pop (remove smallest). At end: heap contains K largest.
  • Top-K smallest elements: use max-heap of size K. Pop when exceeds K.
  • Why K-size heap works: O(n log K) instead of O(n log n) sort — better when K << n
Simple MinHeap for interviews
MinHeap implementation — memorize this
class MinHeap {
    constructor() { this.heap = []; }

    push(val) {
        this.heap.push(val);
        this.#bubbleUp();
    }

    pop() {
        const top = this.heap[0];
        const last = this.heap.pop();
        if (this.heap.length) { this.heap[0] = last; this.#sinkDown(); }
        return top;
    }

    peek() { return this.heap[0]; }
    size() { return this.heap.length; }

    #bubbleUp() {
        let i = this.heap.length - 1;
        while (i > 0) {
            const parent = Math.floor((i-1)/2);
            if (this.heap[parent] <= this.heap[i]) break;
            [this.heap[parent], this.heap[i]] = [this.heap[i], this.heap[parent]];
            i = parent;
        }
    }
    // sinkDown: similar — swap with smaller child until heap property holds
}

Trie + Greedy

Trie: prefix tree for fast string prefix operations. Greedy: make the locally optimal choice at each step — works when local optimal = global optimal (and doesn't always work — know when it fails).

Trie (Prefix Tree)
✓
Trie — implementation + applications
Insert, search, startsWith from scratch. Auto-complete, prefix problems.
must · implement from scratch
Trie implementation — know this cold
Trie — insert, search, startsWith
class TrieNode {
    constructor() {
        this.children = {};   // char → TrieNode
        this.isEnd = false;   // marks end of a word
    }
}

class Trie {
    constructor() { this.root = new TrieNode(); }

    insert(word) {
        let node = this.root;
        for (const ch of word) {
            if (!node.children[ch]) node.children[ch] = new TrieNode();
            node = node.children[ch];
        }
        node.isEnd = true;
    }

    search(word) {
        let node = this.root;
        for (const ch of word) {
            if (!node.children[ch]) return false;
            node = node.children[ch];
        }
        return node.isEnd;  // must be end of a word
    }

    startsWith(prefix) {
        let node = this.root;
        for (const ch of prefix) {
            if (!node.children[ch]) return false;
            node = node.children[ch];
        }
        return true;  // just need path to exist
    }
}
// O(L) for insert/search/startsWith where L = word length
// Space: O(total characters across all words)

Node.js — Auth + Production API Patterns

You know basic Express. This phase: production-grade auth (JWT + refresh tokens), middleware architecture, rate limiting, input validation, and error handling. By end of this: your API should handle auth the way real companies do.

Build this auth system — every topic is a piece of it
✓
JWT Auth — Access token + Refresh token
Sign, verify, decode, expiry, refresh token rotation, storage strategy
must
Exactly what to learn
  • JWT structure: header.payload.signature. Payload is base64 — NOT encrypted, just signed. Never put sensitive data in payload.
  • Access token: short-lived (15 min). Sent in Authorization header: Bearer [token]. Stateless.
  • Refresh token: long-lived (7 days). Stored in HttpOnly cookie. Used to get new access token. Can be revoked (store in Redis or DB).
  • Token refresh flow: access token expires → frontend automatically calls /auth/refresh → server checks refresh token → issues new access token → frontend retries original request.
  • Refresh token rotation: every time refresh token is used, issue a new one and invalidate the old. Detects token theft.
Implementation to build
JWT auth — routes to implement
// POST /auth/register — hash password (bcrypt), create user, return tokens
// POST /auth/login    — verify password, return access + refresh tokens
// POST /auth/refresh  — verify refresh token, issue new access token
// POST /auth/logout   — invalidate refresh token (delete from Redis/DB)

// auth middleware — protects private routes
function authenticate(req, res, next) {
    const token = req.headers.authorization?.split(' ')[1];
    if (!token) return res.status(401).json({ error: 'No token' });
    try {
        req.user = jwt.verify(token, process.env.JWT_SECRET);
        next();
    } catch (err) {
        res.status(401).json({ error: 'Invalid or expired token' });
    }
}
// Packages: jsonwebtoken, bcryptjs, cookie-parser (for HttpOnly cookies)

Error handling + Rate limiting + Middleware architecture
Global error handler, custom error classes, express-rate-limit, middleware ordering
must
Exactly what to learn

MongoDB — aggregation pipeline
✓
MongoDB Aggregation Pipeline
$match, $group, $sort, $project, $lookup, $unwind — the analytics queries
must
Exactly what to learn
  • Aggregation pipeline: array of stages, each transforms the documents flowing through
  • $match: filter documents (like WHERE in SQL)
  • $group: group by field and accumulate (like GROUP BY + aggregates in SQL). _id: "$field" is the group key.
  • $sort, $limit, $skip: sort and paginate results
  • $project: include/exclude fields, add computed fields (like SELECT with aliases)
  • $lookup: join documents from another collection (like SQL JOIN)
  • $unwind: deconstruct array field — each array element becomes a separate document
Aggregation example — from your future Swiggy-like project
MongoDB aggregation — total revenue per restaurant this month
db.orders.aggregate([
    { $match: {
        status: "completed",
        createdAt: { $gte: new Date("2025-01-01") }
    }},
    { $group: {
        _id: "$restaurantId",
        totalRevenue: { $sum: "$amount" },
        orderCount: { $sum: 1 },
        avgOrderValue: { $avg: "$amount" }
    }},
    { $sort: { totalRevenue: -1 }},
    { $limit: 10 },
    { $lookup: {
        from: "restaurants",
        localField: "_id",
        foreignField: "_id",
        as: "restaurant"
    }},
    { $unwind: "$restaurant" },
    { $project: {
        restaurantName: "$restaurant.name",
        totalRevenue: 1,
        orderCount: 1
    }}
])

MongoDB Indexing + Schema Design
createIndex, compound indexes, text indexes, embedding vs referencing
must
Exactly what to learn
  • When to embed vs reference: embed when data is always accessed together, rarely changes, and doesn't have its own lifecycle (order items → embed in order). Reference when data is shared, large, or has independent lifecycle (products, users).
  • createIndex: db.collection.createIndex({ field: 1 }). 1 = ascending, -1 = descending.
  • Compound index: createIndex({ userId: 1, createdAt: -1 }). Supports queries filtering by userId OR userId+createdAt, NOT createdAt alone.
  • Text index: for full-text search. createIndex({ name: "text", description: "text" }). Then $text: { $search: "query" }.
  • Add indexes for: all foreign key references, any field in $match stages of aggregations, frequently queried fields
