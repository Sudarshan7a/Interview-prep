Section 01

Tree Structure + TreeNode

The terminology, the JavaScript class, and the mental models that make recursive solutions obvious.

A binary tree is a hierarchical structure where each node has at most two children — left and right. Trees are recursive by nature: every subtree is itself a tree. This is why recursive solutions feel natural — you solve the problem for the root, then trust that the same function solves it for the children.

Example Binary Tree — used throughout this guide
Height = 3 (root to deepest leaf)
Depth of root = 0
Nodes = 7
Leaves = 1,3,6,9
JavaScriptTreeNode class + terminology
// Standard TreeNode — given in LeetCode problems
class TreeNode {
    constructor(val = 0, left = null, right = null) {
        this.val   = val;
        this.left  = left;
        this.right = right;
    }
}

// Build a tree from array (level-order, null = no node)
function buildTree(arr) {
    if (!arr.length) return null;
    const root = new TreeNode(arr[0]);
    const queue = [root];
    let i = 1;
    while (queue.length && i < arr.length) {
        const node = queue.shift();
        if (arr[i] !== null) { node.left  = new TreeNode(arr[i]); queue.push(node.left); }
        i++;
        if (i < arr.length && arr[i] !== null) { node.right = new TreeNode(arr[i]); queue.push(node.right); }
        i++;
    }
    return root;
}

// Key terminology:
// Root:   top node (depth 0, no parent)
// Leaf:   node with no children (left === null && right === null)
// Height: longest path from root to any leaf (root-only tree has height 0)
// Depth:  distance from root to a node (root has depth 0)
// Level:  all nodes at the same depth
// Balanced: height difference between left/right subtrees ≤ 1 at every node
// Full:   every node has 0 or 2 children
// Complete: all levels filled except possibly the last, filled left to right
// Perfect: all internal nodes have 2 children, all leaves at same level
The recursive mental model for trees: Almost every tree problem can be solved by asking: "What does my function need to return, and how does the parent node compute its answer from the left and right children's answers?" Trust the recursion — assume the function works correctly on subtrees, then implement just the root's logic. Base case: null node → return 0, null, true, or whatever makes sense for the problem.

Section 02

The 4 Traversals

Every tree problem uses one of these traversals. Know the order, know when to use each, know both recursive and iterative implementations.
Preorder
Root → Left → Right
4 → 2 → 1 → 3 → 7 → 6 → 9
Process root BEFORE children. Use for: copying/serializing tree, prefix expression evaluation, finding path to node.
Inorder
Left → Root → Right
1 → 2 → 3 → 4 → 6 → 7 → 9
BST inorder gives SORTED output. Use for: BST validation, kth smallest/largest, recover BST.
Postorder
Left → Right → Root
1 → 3 → 2 → 6 → 9 → 7 → 4
Process children BEFORE root. Use for: deleting tree, computing height/size from bottom up, evaluating expression trees.
Level Order
Level by Level (BFS)
4 → 2, 7 → 1, 3, 6, 9
Use queue. Use for: level averages, right side view, zigzag traversal, minimum depth.
JavaScriptAll 4 traversals — recursive and iterative
// ── RECURSIVE versions (clean and preferred in interviews) ────

function preorder(root) {
    if (!root) return [];
    return [root.val, ...preorder(root.left), ...preorder(root.right)];
}

function inorder(root) {
    if (!root) return [];
    return [...inorder(root.left), root.val, ...inorder(root.right)];
}

function postorder(root) {
    if (!root) return [];
    return [...postorder(root.left), ...postorder(root.right), root.val];
}

// ── ITERATIVE inorder (most commonly asked iterative) ─────────
function inorderIterative(root) {
    const result = [], stack = [];
    let curr = root;

    while (curr !== null || stack.length > 0) {
        // Go as far left as possible, pushing each node
        while (curr !== null) {
            stack.push(curr);
            curr = curr.left;
        }
        // Process the node (leftmost unprocessed)
        curr = stack.pop();
        result.push(curr.val);
        // Move to right subtree
        curr = curr.right;
    }
    return result;
}

// ── ITERATIVE preorder ────────────────────────────────────────
function preorderIterative(root) {
    if (!root) return [];
    const result = [], stack = [root];

    while (stack.length) {
        const node = stack.pop();
        result.push(node.val);
        // Push right first so left is processed first (LIFO)
        if (node.right) stack.push(node.right);
        if (node.left)  stack.push(node.left);
    }
    return result;
}

// ── LEVEL ORDER (BFS with queue) ──────────────────────────────
function levelOrder(root) {
    if (!root) return [];
    const result = [], queue = [root];

    while (queue.length) {
        const levelSize = queue.length, level = [];
        for (let i = 0; i < levelSize; i++) {
            const node = queue.shift();
            level.push(node.val);
            if (node.left)  queue.push(node.left);
            if (node.right) queue.push(node.right);
        }
        result.push(level);
    }
    return result;
}
Which traversal to use — the decision rule:

Process root BEFORE subtrees → Preorder (root first, good for path problems, serialization)
Need sorted order from BST → Inorder (only traversal that gives sorted output from BST)
Compute something from bottom up → Postorder (children computed before parent, good for height/size)
Process level by level, shortest path → Level Order (BFS, minimum depth problems)
Section 03

Binary Search Tree (BST)

A BST is a binary tree with the ordering property: left subtree values < root value < right subtree values. This property must hold for ALL nodes — not just immediate children.

BST is the tree equivalent of a sorted array — it allows O(log n) search, insert, and delete on average. The BST property: for every node, ALL values in its left subtree are smaller, and ALL values in its right subtree are larger.

Common BST misconception: The BST property must hold for the ENTIRE subtree, not just immediate children. The tree [5, 4, 6, 3, ?, ?, 3] is INVALID as a BST because node 3 is in the right subtree of 5 but 3 < 5. When validating a BST, you must pass min/max bounds down the recursion, not just compare a node to its children.
JavaScriptBST operations — search, insert, delete, validate
// ── SEARCH in BST — O(log n) avg, O(n) worst (skewed) ────────
function searchBST(root, val) {
    if (!root || root.val === val) return root;
    return val < root.val
        ? searchBST(root.left, val)
        : searchBST(root.right, val);
}

// ── INSERT into BST ───────────────────────────────────────────
function insertBST(root, val) {
    if (!root) return new TreeNode(val); // base case: insert here
    if (val < root.val) root.left  = insertBST(root.left, val);
    else               root.right = insertBST(root.right, val);
    return root;
}

// ── VALIDATE BST — O(n) ───────────────────────────────────────
// Key: pass min and max bounds down the recursion
function isValidBST(root, min = -Infinity, max = Infinity) {
    if (!root) return true;
    if (root.val <= min || root.val >= max) return false;
    return isValidBST(root.left, min, root.val) &&   // left: max = root.val
           isValidBST(root.right, root.val, max);      // right: min = root.val
}

// ── DELETE from BST — O(log n) avg ───────────────────────────
function deleteBST(root, key) {
    if (!root) return null;

    if (key < root.val) {
        root.left = deleteBST(root.left, key);
    } else if (key > root.val) {
        root.right = deleteBST(root.right, key);
    } else {
        // Found the node to delete — 3 cases:
        if (!root.left)  return root.right;  // no left child
        if (!root.right) return root.left;   // no right child

        // Has both children: replace with inorder successor
        // (smallest value in right subtree)
        let successor = root.right;
        while (successor.left) successor = successor.left;
        root.val   = successor.val;
        root.right = deleteBST(root.right, successor.val);
    }

    return root;
}

// ── INORDER SUCCESSOR of a node in BST ───────────────────────
// Next larger value = leftmost node in right subtree
function inorderSuccessor(root, p) {
    let successor = null;
    while (root) {
        if (p.val < root.val) { successor = root; root = root.left; }
        else                  root = root.right;
    }
    return successor;
}
Section 04

Interview Framework for Tree Problems

What to say and draw before writing any recursive code.
1
Draw the tree — always
Never start coding a tree problem without drawing it. A 5-7 node example is enough. Draw the example tree given in the problem, or make one up. This clarifies the traversal order and edge cases (null nodes, single node, skewed tree).
"Let me draw the tree. [Draws boxes and arrows]. For this problem I'll trace what happens at node 4 (root), then at node 2 (left child), then at the leaves. This helps me see the recursive structure."
2
Identify: DFS or BFS? Preorder, Inorder, or Postorder?
Ask: "Do I need the root's answer to compute children?" → Preorder. "Do I need children's answers to compute root?" → Postorder. "Need BST sorted order?" → Inorder. "Level by level?" → BFS. State the traversal explicitly before coding.
"I need to compute the height from the leaves upward — each node needs the heights of its children before computing its own height. That's postorder DFS."
3
Define the recursive function's contract
The most important step. Say out loud: "My function takes a node and returns [X]." Be specific about what X is. Height? Boolean? List of values? The return type determines how you combine left and right subtree results. Incorrect return type → incorrect recursive combination.
"My function takes a node and returns the height of the subtree rooted at that node. For null: return -1 (or 0 depending on convention). For a leaf: return 0. For any other node: 1 + max(height(left), height(right))."
4
Write the base case first
Always the first line. What does the function return for null? For a leaf? These are the anchors that prevent infinite recursion. Most tree base cases: if (!node) return 0; or if (!node) return null;. Write it before anything else.
"Base case: if the node is null, return 0. This handles leaf node children and empty subtrees. Every recursive call reduces the problem toward this base case."
5
Trust the recursion — don't trace manually
Once you've defined the contract and base case: assume the recursive calls work correctly on subtrees. Don't trace through the entire recursion in your head — that's what the runtime does. Just implement: "given that left gives me X and right gives me Y, what does this node return?" Test with one small example after.
"I trust that height(root.left) correctly returns the height of the left subtree. I trust the same for root.right. Given those two values, this node's height is 1 + max(left, right). Let me verify with the root: left height=2, right height=1, root height=3."

Problem 01 of 05Easy
Maximum Depth of Binary Tree
LeetCode #104 · leetcode.com/problems/maximum-depth-of-binary-tree
1
Problem: Find the maximum depth (height) of a binary tree. Depth = number of nodes along the longest path from root to a leaf.
2
Traversal: Postorder DFS — we need children's depths before computing the node's depth. "Bottom-up" computation.
3
Recursive contract: Function returns the depth of the subtree rooted at node. Null → 0. Any node → 1 + max(depth(left), depth(right)).
4
BFS alternative: Level-order traversal, count the number of levels. Each level iteration increments depth. Same O(n) time, O(n) space.
Interviewer
Find the maximum depth of a binary tree.
You
Is depth defined as number of nodes or number of edges? The LeetCode convention is nodes — a single-node tree has depth 1.
Interviewer
Number of nodes.
You
I'll use postorder DFS. My function returns the depth of the subtree at each node. For null: return 0. For any node: 1 plus the maximum of the depths of the left and right subtrees. I trust that the recursive calls give me the correct depths for the subtrees — I just implement the root's computation.
Interviewer
Can you also do it iteratively?
You
Yes — BFS. Use a queue, process level by level. Each complete level increments depth. When the queue is empty, return depth. Same O(n) time but O(n) space for the queue vs O(h) space for recursion. For a balanced tree, BFS uses more space (bottom level has n/2 nodes). For a skewed tree, DFS uses more (call stack depth n). Both are valid — I'd pick DFS for its simplicity.
JavaScriptMaximum Depth — DFS postorder O(n)
// Recursive — postorder (children computed before parent)
function maxDepth(root) {
    if (!root) return 0;                         // base case
    const leftDepth  = maxDepth(root.left);
    const rightDepth = maxDepth(root.right);
    return 1 + Math.max(leftDepth, rightDepth);
}

// One-liner version (same logic, more compact)
const maxDepth2 = root =>
    root ? 1 + Math.max(maxDepth2(root.left), maxDepth2(root.right)) : 0;

// BFS iterative (counts levels)
function maxDepthBFS(root) {
    if (!root) return 0;
    let depth = 0;
    const queue = [root];
    while (queue.length) {
        const levelSize = queue.length;
        for (let i = 0; i < levelSize; i++) {
            const node = queue.shift();
            if (node.left)  queue.push(node.left);
            if (node.right) queue.push(node.right);
        }
        depth++;
    }
    return depth;
}
Time: O(n) — visit every node once Space: O(h) — call stack height (O(log n) balanced, O(n) skewed)
  • Empty tree (root=null): Returns 0 immediately. Correct.
  • Single node: Both children are null → depth = 1 + max(0, 0) = 1. Correct.
  • Skewed tree (linked list shape): Depth = n. DFS call stack = n frames. Potential stack overflow for very large n. BFS uses O(1) queue space here.
  • Minimum depth vs Maximum depth: Minimum depth (#111) is trickier — must reach a LEAF (not just null). A node with one null child is not at minimum depth. Must check: if no left child, only recurse right (and vice versa).
Problem 02 of 05Easy
Symmetric Tree
LeetCode #101 · leetcode.com/problems/symmetric-tree
1
Problem: Check if a binary tree is symmetric (mirror image of itself around its center).
2
Key insight: Don't try to check the tree against itself. Instead, create a helper function that checks if two nodes (the left and right subtrees) are mirrors of each other. Mirror: their values are equal AND the left's left mirrors the right's right AND the left's right mirrors the right's left.
3
Recursive contract: isMirror(left, right) returns true if the two subtrees are mirrors. Base cases: both null → true. One null → false. Values differ → false.
4
The mirroring pattern: isMirror(left, right) → check isMirror(left.left, right.right) and isMirror(left.right, right.left). The left-right swap is the key insight.
Interviewer
Is this tree symmetric around its center?
You
The tree is symmetric if its left and right subtrees are mirrors of each other. I'll write a helper: isMirror(left, right). This checks if two subtrees are mirror images. For two nodes to be mirrors: their values must match AND the left node's left subtree mirrors the right node's right subtree AND the left node's right mirrors the right node's left — the cross-check.
Interviewer
What's the base case?
You
If both nodes are null — they're mirrors (empty trees are mirrors). If exactly one is null — not mirrors (asymmetric). If values differ — not mirrors. Otherwise check the cross-mirroring of children recursively.
Interviewer
Can you do it iteratively?
You
Yes — use a queue. Enqueue pairs of nodes that should be mirrors: (root.left, root.right). Each iteration: dequeue a pair, check values, enqueue their mirror children — (left.left, right.right) and (left.right, right.left). If any pair mismatches → return false. Queue empty → return true.
JavaScriptSymmetric Tree — O(n) recursive and iterative
// Recursive
function isSymmetric(root) {
    return isMirror(root.left, root.right);
}

function isMirror(left, right) {
    if (!left && !right) return true;   // both null → mirror
    if (!left || !right) return false;  // one null → not mirror
    return left.val === right.val &&
           isMirror(left.left, right.right) &&  // cross-check!
           isMirror(left.right, right.left);
}

// Iterative using queue of pairs
function isSymmetricIterative(root) {
    const queue = [[root.left, root.right]];

    while (queue.length) {
        const [left, right] = queue.shift();
        if (!left && !right) continue;
        if (!left || !right || left.val !== right.val) return false;
        queue.push([left.left, right.right]);   // cross-enqueue
        queue.push([left.right, right.left]);
    }
    return true;
}
Time: O(n) — visit each node once Space: O(h) recursive / O(n) iterative
  • Single node: root.left = null, root.right = null. isMirror(null, null) = true. Correct.
  • All same values [1,1,1,1,1]: All value checks pass. Structure must also be symmetric. The function checks structure through the base cases (null checks).
  • The cross-check is the key: isMirror(left.left, right.right) — not isMirror(left.left, right.left). Many students get this wrong. Remember: mirror means left's left matches right's right, and left's right matches right's left.
Problem 03 of 05Medium
Lowest Common Ancestor of a Binary Tree
LeetCode #236 · leetcode.com/problems/lowest-common-ancestor-of-a-binary-tree
1
Problem: Find the lowest common ancestor (LCA) of two nodes p and q in a binary tree. The LCA is the deepest node that is an ancestor of both p and q.
2
Key insight: During a DFS, if we find p or q, we return it. If a node's left subtree returns a non-null value AND the right subtree returns non-null → this node is the LCA (p and q are on different sides). If only one side returns non-null → the LCA is in that subtree.
3
Recursive contract: Function returns: the node p or q if found in this subtree, or null if neither is in this subtree, or the LCA itself if both are found below this node.
4
The 3-case return logic: (1) Current node is p or q → return it. (2) Both left and right return non-null → current is LCA, return current. (3) Only one side returns non-null → return that side's result (LCA is deeper in that subtree).
Interviewer
Find the lowest common ancestor of two nodes in a binary tree.
You
I'll use postorder DFS. The key insight: during the traversal, if I find p in the left subtree and q in the right subtree (or vice versa), the current node is the LCA. If both are in the same subtree, the LCA is deeper.
You
My function returns either p, q, their LCA, or null. Base case: null → null. If current node is p or q → return current node. Then recurse on left and right. If both left and right return non-null → current node is the LCA, return it. Otherwise return whichever is non-null.
Interviewer
What if one of p or q is an ancestor of the other?
You
Handled correctly. Say p is the ancestor of q. When we reach p, we immediately return p (before searching further). The function never finds q separately — it just returns p. The caller sees non-null from one side, null from the other — propagates p upward. The LCA is p itself. Correct, because p is an ancestor of q, so it's the deepest node that's an ancestor of both.
JavaScriptLowest Common Ancestor — O(n)
function lowestCommonAncestor(root, p, q) {
    // Base case: null node or found p or q
    if (!root || root === p || root === q) return root;

    // Search in both subtrees
    const left  = lowestCommonAncestor(root.left, p, q);
    const right = lowestCommonAncestor(root.right, p, q);

    // If both sides found something: current is the LCA
    if (left && right) return root;

    // Otherwise return whichever side found something
    return left || right;
}

// For BST specifically — use BST property for O(log n):
function lowestCommonAncestorBST(root, p, q) {
    if (!root) return null;
    // Both values are less → LCA is in left subtree
    if (p.val < root.val && q.val < root.val) return lowestCommonAncestorBST(root.left, p, q);
    // Both values are greater → LCA is in right subtree
    if (p.val > root.val && q.val > root.val) return lowestCommonAncestorBST(root.right, p, q);
    // They're on different sides → current is LCA
    return root;
}
Time: O(n) general tree / O(log n) BST Space: O(h) for recursive call stack
  • p is ancestor of q: When we reach p, return p immediately. q is never "found" separately. The function correctly returns p as the LCA.
  • p and q are on opposite sides: left returns p (or non-null from p's direction), right returns q. left && right → return root. Correct.
  • root is p or q: Returns root immediately. Everything below is searched implicitly (the problem guarantees both nodes exist). LCA = root. Correct.
  • BST LCA is O(log n): Each step eliminates half the tree using the BST property. No need to search both sides.
Problem 04 of 05Medium
Validate Binary Search Tree
LeetCode #98 · leetcode.com/problems/validate-binary-search-tree
1
Problem: Given a binary tree root, determine if it's a valid BST. All left subtree values must be strictly less than node.val, and all right subtree values must be strictly greater — for every node.
2
Wrong approach: Only checking parent vs immediate children is insufficient. Tree [5, 4, 6, null, null, 3, 7] appears valid child-by-child, but 3 is in the right subtree of 5, violating BST property (3 < 5).
3
Correct approach — bounds propagation: Pass min and max valid value bounds down the recursion. At each node: value must be strictly between min and max. Going left → max = node.val. Going right → min = node.val.
4
Alternative — inorder: A valid BST's inorder traversal gives strictly increasing values. Traverse inorder, track the previous value — if current ≤ previous, invalid. O(n) time, O(n) or O(h) space.
Interviewer
Is this a valid BST?
You
The common mistake is only checking immediate children. The BST property must hold for the ENTIRE subtree. A node in the right subtree must be larger than all ancestors, not just its parent.
You
I'll pass min and max bounds down the recursion. Root: (-Infinity, Infinity). When going left from value V, the new max is V. When going right, the new min is V. At each node: value must be strictly between min and max. This enforces the BST property across all ancestors.
Interviewer
What about integer overflow for min/max values?
You
Using -Infinity and Infinity avoids overflow — they compare correctly with any number in JavaScript. In Java, you'd use Long.MIN_VALUE and Long.MAX_VALUE instead of Integer limits, since node values might be at integer boundaries.
Interviewer
Can you solve it another way?
You
Inorder traversal — a valid BST gives strictly increasing values inorder. Traverse and track the previous value. If current node's value ≤ previous, invalid. Clean O(n) solution that exploits the core BST property directly.
JavaScriptValidate BST — bounds propagation O(n)
// Approach 1: bounds propagation (cleaner, O(h) space)
function isValidBST(root, min = -Infinity, max = Infinity) {
    if (!root) return true;
    if (root.val <= min || root.val >= max) return false;
    return isValidBST(root.left,  min, root.val) &&  // left: update max
           isValidBST(root.right, root.val, max);     // right: update min
}

// Approach 2: inorder traversal — sorted if valid BST
function isValidBST2(root) {
    let prev = -Infinity;

    function inorder(node) {
        if (!node) return true;
        if (!inorder(node.left)) return false;  // check left subtree
        if (node.val <= prev) return false;      // check current > previous
        prev = node.val;
        return inorder(node.right);               // check right subtree
    }

    return inorder(root);
}
Time: O(n) — visit every node once Space: O(h) — call stack depth
  • The classic trap [5,1,4,null,null,3,6]: Node 4 is right child of 5. 4 < 5 — invalid! Bounds: right subtree has min=5. Node 4 is not > 5. isValidBST(4, 5, Infinity) → 4 ≤ 5 → return false. Correct.
  • Strictly greater/less: Equal values are invalid. BST requires STRICT inequality. The check is root.val <= min (not <) and root.val >= max (not >).
  • Integer boundary values: If node values can be Integer.MIN_VALUE or Integer.MAX_VALUE, using int limits fails. Use Long or -Infinity/Infinity in JS.
  • Inorder approach — prev is a closure variable: In JavaScript, prev in the outer scope is shared across all inorder calls. This correctly tracks the globally previous inorder value across the entire traversal.
Problem 05 of 05Hard
Binary Tree Maximum Path Sum
LeetCode #124 · leetcode.com/problems/binary-tree-maximum-path-sum
1
Problem: Find the maximum path sum in a binary tree. A path can start and end at any node. Can go through the root or not. Nodes can have negative values.
2
The key distinction: What the recursive function returns vs what it updates. The function returns the maximum "arm" from this node upward (going either left or right, not both). But internally it also updates the global max which CAN include both arms (path that bends through this node).
3
Why two different values: A path that bends through a node (left arm + node + right arm) can't be extended upward — it would create a fork. So: the function returns the best single-arm (for parent to use), but tracks the best bent-path (through this node) globally.
4
Negative subtrees: Use max(0, left) and max(0, right). If a subtree has negative sum, don't include it — set its contribution to 0 (ignore that arm). This handles the case where the optimal path doesn't go through a child.
Interviewer
Find the maximum path sum through any path in the tree.
You
This is the classic "global max vs return value" tree problem. My recursive function does two things: (1) computes and updates a global max that can include both the left and right arms of the current node. (2) returns the best single arm extending upward, for the parent to use.
You
For each node: the best left arm = max(0, recurse(left)) — the max(0) handles negative subtrees by ignoring them. Same for right arm. The path through this node = node.val + left arm + right arm. Update global max. Return node.val + max(left arm, right arm) to parent.
Interviewer
Why max(0, left)?
You
If the left subtree has a negative sum, including it would decrease the path sum. We're better off not going left at all — contribution is 0. The max(0, ...) handles this gracefully without special cases.
Interviewer
What if all nodes are negative?
You
Initialize globalMax to -Infinity. At each node, the path through just that single node (ignoring both arms) = node.val + 0 + 0 = node.val. This is compared against globalMax. The most negative single node becomes the answer if all nodes are negative.
JavaScriptMaximum Path Sum — O(n) postorder with global max
function maxPathSum(root) {
    let globalMax = -Infinity; // works for all-negative trees

    function maxGain(node) {
        if (!node) return 0;

        // Max gain from left/right: 0 if negative (don't extend)
        const leftGain  = Math.max(0, maxGain(node.left));
        const rightGain = Math.max(0, maxGain(node.right));

        // Best path THROUGH this node (may go left + right, can't extend up)
        const pathThroughNode = node.val + leftGain + rightGain;
        globalMax = Math.max(globalMax, pathThroughNode);

        // Return best single-arm for parent to use
        return node.val + Math.max(leftGain, rightGain);
    }

    maxGain(root);
    return globalMax;
}
Time: O(n) — postorder, visit each node once Space: O(h) — recursion stack
  • All negative [-3, -2, -1]: globalMax starts at -Infinity. After root -3: leftGain=max(0,-2)=0, rightGain=max(0,-1)=0, path=-3, globalMax=-3. Return -3. Correct (best path is just the root).
  • Single node [5]: leftGain=0, rightGain=0, path=5, globalMax=5. Return 5. Correct.
  • Path doesn't go through root: e.g., [1, 2, 3]. Through root: 1+2+3=6. The maxGain function computes this at the root level. globalMax captures it. Correct even when the optimal path does go through root.
  • Left-only or right-only path: If left has negative gain, leftGain=0, path = node.val + 0 + rightGain. Effectively a right-only path. The max(0, ...) handles this automatically.

15 Interview Questions

Answer out loud before expanding. Trees appear in 30–40% of all technical interviews at product companies.
CoreWhat are the 4 traversals? When do you use each?▼
Preorder (Root→Left→Right): Process root before children. Use when: copying a tree, serializing, finding paths from root, problems where parent info is needed before processing children. Inorder (Left→Root→Right): For BST, gives sorted output. Use when: BST validation (previous value tracking), kth smallest/largest, recovering swapped nodes. Postorder (Left→Right→Root): Process children before root. Use when: computing bottom-up values (height, size, diameter), deleting tree, expression evaluation. Level Order (BFS): Process level by level. Use when: shortest path, level averages, right side view, minimum depth, zigzag traversal. Rule: need root before children → preorder. Need children before root → postorder. Need sorted BST order → inorder. Need levels → BFS.
CoreWhat is the recursive mental model for tree problems?▼
Three steps: (1) Define the contract: "my function takes a node and returns [X]." Be specific about what X is — height, boolean, list, node, etc. (2) Write the base case first: what does the function return for null? For a leaf? (3) Trust the recursion: assume the function correctly computes X for the left and right subtrees. Implement ONLY the current node's computation using left and right results. Never trace through the full recursion mentally — that's what the runtime does. Example for height: "returns the height of the subtree." Base: null → 0. Current: 1 + max(height(left), height(right)). The 3-step process works for 90% of tree problems. The hardest part is step 1 — defining exactly what the function returns.
TrapWhy does BST validation require bounds propagation and not just checking immediate children?▼
The BST property requires ALL values in the left subtree to be less than the root — not just the immediate left child. Consider [5, 4, 6, null, null, 3, 7]. Node 6 is the right child of 5, which looks valid (6 > 5). But 3 is the left child of 6 — and while 3 < 6 (valid locally), 3 < 5 (violates BST property for the whole tree). The correct approach: propagate min/max bounds downward. Going left from value V: max bound becomes V. Going right from V: min bound becomes V. At each node: value must be strictly between its inherited min and max. This catches any violation anywhere in the tree, not just at the current node's children.
InterviewExplain the LCA algorithm. How does it differ for BST vs general tree?▼
General tree (O(n)): DFS that returns: p if it finds p, q if it finds q, their LCA if both found below, null if neither found. At any node: if both left and right return non-null, current is the LCA. Otherwise return whichever is non-null. This works because the first node where p and q are on opposite sides is the LCA. BST (O(log n)): Use the BST property. If both p and q are less than root → LCA is in left subtree. If both greater → right subtree. Otherwise → root is the LCA (they split here). O(log n) vs O(n) — exploits ordering. Interview tip: always ask "is this a BST or general binary tree?" before coding LCA — it determines which O(log n) vs O(n) applies and which algorithm to code.
InterviewWhat is the "global max vs return value" pattern? Give an example.▼
Some tree problems require computing a value that includes both the left and right branches of a node (which forms a "bent" path that can't extend upward), while also returning something to the parent. These need two separate values: (1) A global variable tracking the best answer seen anywhere. (2) The function's return value — a "straight arm" usable by the parent. Examples: Maximum Path Sum: function returns max single arm (left or right + node). Globally tracks node + left arm + right arm (bent path). Diameter of Binary Tree: function returns max depth of subtree. Globally tracks left depth + right depth (the diameter through this node). Pattern: whenever the optimal answer might "bend" through a node (using both children), use this pattern. The global max captures the bent paths; the return value captures the straight extension for the parent.
CoreHow do you check if a binary tree is balanced? What's O(n) vs O(n²)?▼
O(n²) naive: For each node, compute height of left and right (O(n) each). Check |leftH - rightH| ≤ 1. Recurse. n nodes × O(n) per node = O(n²). O(n) optimal: Compute height AND check balance in a single postorder pass. If a subtree is unbalanced, return a sentinel (-1 or Infinity). At each node: compute leftH = height(left). If leftH = -1, return -1 (unbalanced). Compute rightH = height(right). If rightH = -1, return -1. If |leftH - rightH| > 1, return -1. Else return 1 + max(leftH, rightH). Final call returns -1 if unbalanced, else the actual height. The key: early return on -1 propagates the "unbalanced" signal without extra work. LeetCode #110. Code the O(n) version — mention the naive is O(n²).
InterviewHow do you construct a binary tree from preorder + inorder traversal?▼
LeetCode #105. Key observations: (1) The first element of preorder is always the root. (2) Find this root value in the inorder array — everything to the left is the left subtree, everything to the right is the right subtree. (3) The number of elements to the left of the root in inorder = size of left subtree. Use this to split the preorder array into left and right subarray. (4) Recursively build left subtree from preorder[1..leftSize] and inorder[0..rootIdx-1]. Right from preorder[leftSize+1..] and inorder[rootIdx+1..]. Optimization: use a HashMap from value to inorder index for O(1) lookup instead of O(n) scan. Total: O(n) time with HashMap, O(n²) without. This is the preorder + inorder version; postorder + inorder is symmetric — last element of postorder is the root.
BSTWhat is the inorder successor in a BST? How do you find it?▼
The inorder successor of node p in a BST is the node with the smallest value greater than p.val — the "next" node in sorted order. Cases: (1) If p has a right child: successor is the leftmost node in p's right subtree (smallest value in right subtree). (2) If p has no right child: successor is the nearest ancestor for which p is in the left subtree. Algorithm (without parent pointers): traverse from root. If root.val > p.val, root is a candidate → save it, go left to find a smaller candidate. If root.val ≤ p.val, go right (successor must be to the right). O(log n) for balanced BST. Used in: BST deletion (replace deleted node with inorder successor), implementing sorted sets. Related: inorder predecessor is the largest value smaller than p — symmetrically, rightmost node in left subtree.
InterviewHow do you serialize and deserialize a binary tree?▼
LeetCode #297. Serialize: preorder traversal with null markers for missing nodes. "4,2,1,null,null,3,null,null,7,6,null,null,9,null,null". Each null explicitly marks absent children. Deserialize: consume tokens from the serialized string. If token is "null", return null. Otherwise create a node, recursively build left child (consuming next tokens), then right child. The preorder serialization uniquely reconstructs the tree. Why preorder (not inorder): inorder of a tree is not unique — multiple trees can have the same inorder. Preorder with nulls IS unique. BFS (level-order) also works — LeetCode's own format uses this. Preorder recursive is cleaner to implement. O(n) time and space for both serialize and deserialize.
TrapWhat's the difference between depth and height? Why does minimum depth need special handling?▼
Depth: distance from root to a specific node. Root has depth 0. Height: longest path from root to any leaf. Leaf has height 0. A tree of one node has depth 0 and height 0. Minimum depth trap (LeetCode #111): Minimum depth is the distance from root to the nearest leaf. A leaf is a node with NO children. The naive recursive solution: minDepth(root) = 1 + min(minDepth(left), minDepth(right)). WRONG! For a tree [1, 2] (root with only a left child), this gives min(depth(2), depth(null)) = min(1, 0) = 0, so depth = 1. But node 1 is NOT a leaf — it has a child. The minimum depth should be 2 (path 1→2). Fix: if a node has only one child, don't consider the null child as reaching a leaf. If left is null, recurse only on right (and add 1). If right is null, recurse only on left. Only if both exist, take the minimum.
InterviewHow do you find the kth smallest element in a BST?▼
LeetCode #230. BST inorder traversal gives sorted ascending order. Find the kth element by doing inorder and stopping at the kth value. Two approaches: (1) Collect all inorder values in an array, return arr[k-1]. O(n) time, O(n) space. (2) Iterative inorder with early exit — stop when you've counted k nodes. O(k + h) time, O(h) space. Iterative version: maintain a counter. Each time you "visit" a node (pop from stack and process), decrement k. When k reaches 0, return that node's value. For a balanced BST this is O(log n + k), better than O(n). Follow-up: if the BST is frequently modified and you need kth smallest repeatedly, augment each node with the size of its left subtree. Then kth smallest is O(log n) — similar to order statistics trees.
CoreWhat's the time and space complexity of tree DFS vs BFS?▼
DFS time: O(n) — visits every node exactly once. DFS space: O(h) where h is the height. This is the recursion call stack depth. For a balanced tree: O(log n). For a skewed tree (like a sorted list inserted into BST): O(n). BFS time: O(n) — same, visits every node once. BFS space: O(w) where w is the maximum width (maximum number of nodes at any level). For a complete binary tree, the last level has n/2 nodes → O(n/2) = O(n). For a skewed tree, every level has 1 node → O(1). When to prefer which: Skewed tree input → prefer BFS (DFS might stack overflow). Very wide tree → prefer DFS (BFS queue too large). For most problems, DFS recursion is cleaner and preferred unless level-by-level processing is needed.
BSTHow do you delete a node from a BST? What are the three cases?▼
Finding the node: binary search in O(log n). Deleting: three cases: (1) Node has no children (leaf): Simply remove it — return null to parent. (2) Node has one child: Replace the node with its only child — return the child to the parent. (3) Node has two children (hardest): Can't simply remove. Instead: find the inorder successor (leftmost node in right subtree — smallest value in right subtree). Copy the successor's value into the current node. Delete the successor from the right subtree (it has at most one child — a right child). This preserves BST property because the successor is the smallest in the right subtree — replacing the node with it maintains all the ordering constraints. Alternatively, use the inorder predecessor (largest in left subtree). O(log n) for balanced BST, O(n) for skewed.
InterviewHow do you find the diameter of a binary tree?▼
LeetCode #543. Diameter = longest path between any two nodes. Path doesn't need to go through root. Uses the "global max vs return" pattern: Function returns: height of subtree (for parent to use). Globally tracks: left depth + right depth (diameter passing through this node). Code: globalDiameter = 0. function depth(node): if null return 0. leftD = depth(left). rightD = depth(right). globalDiameter = max(globalDiameter, leftD + rightD). Return 1 + max(leftD, rightD). The diameter at each node = leftD + rightD (not +1 — we're counting edges, not nodes). Return globalDiameter after the root call. Key insight: the diameter might pass through any node, not just the root. The global variable captures the best diameter found at any node during the postorder traversal. O(n) time, O(h) space.
InterviewExplain the "path sum III" approach. Why is prefix sum needed?▼
LeetCode #437. Count paths summing to targetSum where paths can start and end at any node (going downward). Naive: at each node, start a new DFS to count paths — O(n²). Optimal (O(n)): use prefix sums. prefixSum[i] = sum from root to node i. For a path from node a to node b to sum to target: prefixSum[b] - prefixSum[a-1] = target. So count how many ancestors have prefixSum = currentPrefix - target. Use a HashMap: count[prefix] = number of paths ending at this sum. DFS: at each node: currentSum += node.val. count[currentSum - target] paths end here. Increment count[currentSum]. Recurse on children. Decrement count[currentSum] when backtracking (remove current node's contribution). The backtracking is critical — we only want ancestor prefix sums, not sibling branches. This is the "prefix sum + DFS + backtracking" pattern.
